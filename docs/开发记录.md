## 对齐：中文数字误判增删字（2026-11-19，源码工作区）

真实素材 `九350-359.wav`（51 条，CPU 实跑 Qwen3-ForcedAligner）中“十万神风军都挡不住”对齐失败：整句标准化把“十万”折算为“100000”，对齐器逐字返回“十”“万”，长度不等被判为增删字。对齐的文字映射改用逐字标准化（不折算数字），参考匹配仍沿用原规则。同一素材对齐失败由 2 条降为 1 条；剩下的“马上撤！”是模型给出零长度字且“撤”晚 2.4 秒，属于真实不可靠结果，保留原时间并标红复核是正确行为。试过把零长度字与相邻字平分时间，真实素材上没有改善，已撤回。后端 413 项通过。

## 光标回车分段、界面性能与浅色配色（2026-11-19，源码工作区）

字幕文字中光标两侧都有文字时按回车，从光标处分成两条：两侧空白与换行不保留，第二条获得焦点；Shift+回车在文字中换行；光标在首尾、编辑被锁定或无法定位时，回车只结束编辑。光标位置先按显示文字映射回原文（显示层会隐藏标点、转换数字），映射不到时提示，不猜测切点。无可靠词时间的新时间标为估计并待复核，有词时间则沿用词间空档。后端 `/api/segment` 的光标与中间分段合并为一个分派表；时间过短时明确报“字幕时间过短”，不再误报“没有完整词边界”。

主题切换原先用整页 `startViewTransition` 截图，并给所有元素加颜色过渡。2000 条字幕时，切换最长一帧约 217ms，30 帧中有 4 帧超过 50ms。现改为即时切换，字幕行加 `content-visibility: auto`：切换时的样式与布局重算由 170–285ms 降到 10–15ms。窗口 `resize` 与波形重绘合并到每帧一次。三次稳定测量：主题切换最长帧 16.7–16.8ms，无超过 50ms 的帧；缩放最长帧 16.8–33.3ms，无超过 50ms 的帧。无头浏览器的基线缩放没有掉帧，真实拖动的体感以实机为准。

浅色配色重新分层：卡片改为白色，面板与中间区域拉开层次；`--muted-2` 在中间区域的对比度由 3.38 提高到 5.4，`--yellow-text` 在卡片上由 4.42 提高到 6.37，绿/红文字均在 6 以上。深色配色和“蓝/绿/黄/红”的语义不变。

验证（实际值）：后端单测 412 项通过；前端与数字回归 159 项通过（`tests/run_frontend_checks.mjs` 用 VS Code 自带的 Electron Node 运行，输出写到 `data/`）；`tests/check_cue_enter_split.py` 真实 Chrome 3 项通过。完整 `tests/browser_smoke.py` 通过 65 项，失败 1 项：第 806 行“改开始时间后对齐记录应失效”，与 HEAD 的结果相同，属既有问题，见[问题与待办](问题与待办.md)。窗口 resize 断言（第 142 行）原为同步断言，现因 resize 按帧合并改为轮询等待。

仍未验证：真实音频与真人长片、真实窗口拖动的体感，以及完整浏览器套件中第 806 行的产品规则。

## 统一标签、局部对齐重试与幻觉处理（2026-11-12，源码工作区）

字幕标签统一为五类：轻微问题（黄）、明显错误（红）、校验通过、校准通过、修改通过；自动通过为蓝，人工修改通过为绿；对齐完成后通过项另显示“对齐通过”，时间异常仍保留红/黄提示。筛选同步为这些标签加“未校验”，内容来源与对齐结果可同时命中；人工改过的字幕即使对齐时发现时间异常，也同时保留“修改通过”和红色时间问题。原识别置信度改称“原识别评分”，并注明它只是模型原始分数，拆条后可能共享，不能当作正确率或对齐准确率。

对齐增加异常词时间检查（零长度、倒序、单词异常拉长、同句跨过长空档）和较短上下文窗口。全局对齐明显偏移时，用原时间附近的局部音频和相邻字幕重试；只有文字边界完整、时间顺序与邻句关系都通过检查才替换，失败仍保留原时间并标红。异常词时间不再用于拆句。Whisper 幻觉规则只标记供人工复核，不再自动置灰或默认不导出；旧工程的自动排除在载入/校验时解除，明确的人工“不导出”决定保留。

同时清理了旧流程残留：幻觉标记不再接受和写入 `auto_exclude`/`automatic_exclusion`（旧工程的自动排除仍在载入时解除）；`normalize_cues` 删除了早已不参与校准的宽度、停顿和语气词参数，响应不再返回恒为 0 的分拆/合并统计；删除前端从未调用的 `/api/segment/merge` 合并接口。前端同时删除了校准已不再生成的“建议合并”碎片提示及其样式、无引用的 `markNoReference`/`highlighted`/`markReview` 及旧行内复核动作分支，并修复手工改字处理中引用已删除变量导致的编辑报错；后端删除无调用的 `drop_interjections` 与只写不读的 `confidence_source`。低“原识别评分”不再自动触发复核，统计条由“疑似”改为“待复核”；未跑内容校验时，时间异常和已确认幻觉标红，其余复核项标黄。只有时间异常、没有内容问题时，“校验通过/校准通过”仍与红色时间问题同时显示。

代码已实现并同步前后端回归用例。本轮后端 325、前端与数字 140、隔离浏览器 58 项通过，测试前后源码一致；在线安装包（不打包依赖和模型）已按当前源码构建，首次启动通过本地 HTTP 安装 27 个依赖，静默安装与卸载后安装目录和桌面快捷方式清理干净。真实模型、公网镜像速度和另一台干净机仍未验证。

模型权重下载与依赖安装分开，下载支持续传、校验和重试，CPU 改走 PyTorch 官方源；完整安装包在构建期由 `tools/prepare_runtime.py` 准备 Qwen/FireRed 共用运行库，安装后不运行 pip，仅模型按需下载。
