# 连续语音首尾碎片与单字字幕修复

日期：2026-11-07
范围：`backend/core/segment.py` 的分段、宽度换行和手动分段逻辑
结果：后端回归 **234 项通过**，浏览器联调 **53 项通过**

## 问题

识别结果本来是一句连贯的话，字幕却被拆成首尾一两个字单独成条；连续说话、声波明显连贯时尤其多。有时句中也会单独出现一个字的字幕。用户要求：

- 一句话不能把首字或尾字单独分出去；
- 一句话中间也不能留下单独一个字，即使超过了每行字数上限；
- 只有原句本来就有标点、或确实存在可验证的停顿，才允许在这些位置断开。

## 根因

1. `split_on_gaps` 只看相邻词的词时间空档。连续语音里 ASR/对齐器仍可能给出 0.6 秒以上的词间空档，旧逻辑直接当作停顿切开，于是“我今天去公园”可能被切成“我 / 今天去公园”这类碎片。
2. 即使边界精修已经生成了 `audio_silences`（真实静音区间），旧逻辑也没有拿它验证词间空档；声波连贯的位置照样能切。
3. `split_text` 按字数上限切分时，末尾可能只剩一个字，例如宽度 7 切出 6+1。
4. `segment_midpoint` 的手动分段只避开词内部，没有要求两侧至少两个字，可能切出“我 / 今天……”。

## 修改

### 1. 词间空档必须有声学静音作证

新增 `_gap_has_audio_support()`：如果字幕带有 `audio_silences` 证据，词间空档内必须存在与 `[prev.end, word.start]` 重叠至少 `max(0.15, min_gap/2)` 秒的静音，才允许按该空档切分；找不到就忽略这个边界。

- 没有 `audio_silences` 的旧工程/旧数据继续沿用原行为，避免破坏历史结果。
- 边界精修给出的真实静音仍然能切，不会把正常停顿一并吞掉。

### 2. 首尾碎片合回原句

`split_on_gaps` 在生成分段前增加了边缘过滤：

- `significant_width()` 只统计 Unicode 字母和数字，标点、空格不算“字”；
- 句首/句尾不足 3 个字，且其余部分至少是它的两倍长，视为碎片；
- 如果原句在该位置本来有标点（如“你好，走吧！”），保留这个切点；
- 不是“见短就合”，左右均衡的 2+2 分段仍然允许，避免把正常短句强行并成一行。

### 3. 句中单字并入相邻段

同一轮过滤里，如果任何分段只含 1 个有效字，就把对应切点删掉，把该字并回前一段或后一段；循环到没有单字段落为止。

### 4. 字数切分不再产生单字行

新增 `_merge_tiny_chunks()` 和 `_rebalance_merge()`：

- `split_text` 返回前检查每一段，少于 2 个有效字就与相邻段合并；
- 合并后如果超过字数上限，会在合并文本里重新找一个两侧都 ≥2 字、且两边都不超限的切点；
- 实在找不到合规切点时宁可不切，保证不会为了满足字数上限制造单字字幕。

### 5. 手动分段同样保护单字

`segment_midpoint` 的候选切点增加 `significant_width(text[:cut]) >= 2` 和 `>= 2` 两侧约束；找不到合规切点就退回常规字数分段，而不是硬切。

### 6. 没有放宽碎片修复

`repair_fragments` 保持原行为：只合并同一原句、间隔不超过 0.25 秒且不超过停顿阈值的真碎片。没有为了这次修复扩大跨停顿合并，避免把两句独立台词误并。

## 已知边界

- 没有词时间或 `audio_silences` 的旧数据只能沿用原逻辑；本次保护不凭空推断静音。
- 如果整条字幕本来只有一个字（例如单独的语气词），它不会被“合并”掉；规则只防止从一句话里孤立出单字。
- 真实录音里极短促的爆破音、多人抢话仍可能让词时间本身不可靠，需要用真实素材复核；自动规则不能替代试听。
- 每行字数上限仍优先遵守；当上限本身小于 2 个字时不会强行制造超限行，界面最小值为 6，正常使用不会触发。
