# 检查问题修复、浏览器全流程与性能实测（2026-11-09）

对应应用 2.3.4。本轮接在只读检查报告之后，完成检查发现问题的修复，并补上最后一轮浏览器全流程复检和 5000 条字幕性能实测。

## 一、本轮修复

### 1. 参考匹配可查询、可取消、有时间上限

- 新增 `backend/core/match_tasks.py`：`MatchTasks` 维护正在执行的匹配任务，提供进度、消息、取消事件和 150 秒时间上限；同一时间只允许一个匹配任务，历史最多保留 32 条，结束后释放活动位置。
- `backend/app.py` 新增 `/api/script/match/status`、`/api/script/match/cancel`；`/api/script/match` 带 `request_id` 时登记为任务，`core/reference_match.match_reference()` 在各阶段调用 `checkpoint(progress, message)`。
- 前端 `runReferenceMatch()` 用请求标识轮询进度，超时或失败时主动取消后端任务；新增取消按钮，取消后保留当前字幕不变。
- 修复点：前端 170 秒超时不再等于后端继续空转；大剧本匹配能看到进度，也能真正停下。

### 2. 工程保存冲突不再连续失败

- `saveProject()` 收到 409 后把工程加入 `projectConflicts` 并停止后续自动保存，保留本页未保存修改，提示“保存冲突，请备份本页并载入最新工程”。
- 新增“备份本页并载入最新工程”按钮：先把本页内容备份到独立工程，再加载服务端最新 revision，避免直接覆盖其他页面的更新。
- 冲突解除后恢复自动保存；页面重新加载时同步按钮显隐。

### 3. 持续断线时可以停止等待、恢复编辑

- 识别/对齐轮询遇到普通网络错误时显示“停止等待，恢复编辑”，点击后停止本页轮询、释放编辑锁，但保留任务标识。
- 恢复连接后通过“继续查询原任务”重新取回结果，避免重复提交；原任务可能仍在后台的提示会明确显示。

### 4. 其他检查项

- `Handler.log_message()` 对尚未建立的 `path`、`command` 使用缺省值，首行请求超时不再抛 `AttributeError`。
- 全局空格快捷键在焦点位于按钮、链接、`summary`、`role=button/checkbox/slider`、视频或对话框内时不再拦截，按钮可以正常用空格激活。
- 应用版本统一升到 2.3.4（后端、帮助页、打包清单、回归记录、README 和文档标题）。

## 二、测试结果

| 项目 | 结果 |
|---|---|
| 后端全量 `tests/run_backend_checks.py` | 279 项全部通过，0 失败 0 错误 |
| 前端函数回归 | 86 项通过（本轮执行；本机命令行没有 Node，未再次复跑） |
| 浏览器全流程 | 54 项全部通过（隔离 Chrome，1536×1000） |
| 5000 条字幕性能 | 快照 3.9 ms，首次渲染 665.4 ms，约 4.17 MB 请求体序列化 9.8 ms，时间设置变更 231 ms |

浏览器覆盖包括：页面启动与面板布局、音量持久化、模型下载/取消/续传（模拟传输）、手动 SRT 对齐、独立 SRT 保存恢复、真实 SRT/MKV 导出、校准与撤销、局部重识别、报告弹窗、波形缩放、乱序剧本来源、上下文多余台词、窄屏和深浅色界面。本轮修正了报告弹窗未关闭导致后续点击被遮挡的问题，并在相关步骤前显式关闭弹窗后复跑。

性能口径：隔离 Chrome 单次测量，5000 条字幕、40 万字符剧本、固定视口；不是逐帧渲染速度，也不是端到端保存耗时。与 2026-11-06 的同类测量（快照 6 ms、首次渲染 879 ms、序列化 9.6 ms、时间设置 174 ms）相比，渲染约快 24%，时间设置略慢；首次渲染仍超过 0.5 秒，大工程首次打开会有可感知停顿，后续可继续优化表格渲染。

## 四、已知边界

- 前端 86 项在另一环境执行，本机没有 Node，未能在当前命令行复跑；后端与浏览器结果均为本机本轮实际结果。
- 浏览器使用合成媒体、模拟识别和模拟对齐，不代表真实大模型对白准确率、速度或 GPU 表现。
- 参考匹配的时间上限为 150 秒，超过后返回可重试错误；极端大剧本仍需按集处理，不能据此宣称 50 万字 + 5000 条一定能在时限内完成。
- 5000 条首次渲染约 0.67 秒，属于可感知停顿；表格仍是整表重建，后续如需进一步缩短可做增量渲染。
- 桌面上的 `SubtitleStudio_2.3.3.zip` 是上一轮发布包，不含本轮修复；如要发布 2.3.4 需重新打包。
