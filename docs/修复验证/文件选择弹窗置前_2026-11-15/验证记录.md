# 文件选择弹窗置前

用户反馈：点击选择素材后，系统文件选择框可能被程序遮住。本轮复查媒体、剧本、SRT、模型目录和导出目录共用的原生选择器。

## 修复

- 原代码只为隐藏父窗口设置顶置属性，没有在真实选择框创建后提升它自身。
- 文件选择框启用Explorer式hook，在WM_INITDIALOG和CDN_INITDONE时获取完整父对话框，设置HWND_TOPMOST并尝试激活；返回0保留系统默认消息处理。
- 文件夹选择框始终注册初始化回调，即使没有历史目录也执行置前；有历史目录时继续恢复位置。
- 窗口API及回调使用指针宽度类型，防止64位句柄截断；只在初始化时处理，不定时持续抢焦点。
- 保留单选、多选、Unicode路径、取消、错误报告和临时父窗口/COM资源释放行为。

## 本轮验证

| 项目 | 结果 |
| --- | --- |
| 文件选择协议回归 | 8项通过，模拟Windows API，不弹真实交互框 |
| 后端完整回归 | 349项通过，见[结果](后端回归.json)及[日志](backend-tests.txt) |
| 前端业务与数字 | 108 + 35项通过，见[结果](前端回归.json) |
| 改动空白检查 | 通过 |
| 真实桌面前后遮挡 | 未完成实测：Computer Use连接失败 |

新增协议用例直接调用原生回调，验证完整文件选择框而非hook子窗口被提升、超过32位的句柄保持完整、焦点请求被Windows拒绝时仍设置Z序、不在普通消息中重复抢焦点，以及无历史目录的文件夹选择取消后资源释放。

桌面工具首次调用、重试及重建JavaScript会话后均返回：`Computer Use native pipe is unavailable: failed to connect native pipe: 系统找不到指定的文件。 (os error 2)`。因此不把真实Windows前台显示或多显示器表现记为验收通过。

源码程序每次从独立进程加载file_dialog.py，重新打开选择框会读取本次修改；已有的打开窗口应先取消。安装版未重新打包。

## 官方依据

- [OFNHookProc](https://learn.microsoft.com/en-us/windows/win32/api/commdlg/nc-commdlg-lpofnhookproc)：Explorer式hook收到的是子窗口句柄，GetParent取得完整选择框。
- [CDN_INITDONE](https://learn.microsoft.com/en-us/windows/win32/dlgbox/cdn-initdone)：在系统完成控件排列后发送初始化完成通知。
- [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)：HWND_TOPMOST控制窗口Z序，不依赖单独的焦点切换。
- [SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)：Windows可能拒绝前台激活请求，不能承诺无条件取得键盘焦点。
