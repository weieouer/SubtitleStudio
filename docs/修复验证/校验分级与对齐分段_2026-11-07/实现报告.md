# 校验分级与对齐分段（2026-11-07）

对应应用 2.3.1。本轮解决四件事：

- 校验结果统一为绿=通过、黄=疑似、红=明显问题；校准和对齐结束后重新校验、刷新标签，并弹窗报告处理前后的条数与各级数量。
- “停顿断句”阈值同时作用于提取和对齐：达到阈值才拆，很短停顿不拆，0 关闭；有可靠参考时，参考句内不拆、参考断句才拆。
- 对齐按“每行字数”把过长字幕分段衔接后面；校准内部的对齐关闭停顿和宽度拆条，保持条数稳定。
- 启动器拒绝复用版本不一致的旧后台。

## 实现内容

### 1. 校验分级与自动报告

- 前端新增 `cueVerificationIssues(cue, options)`，集中判断一条字幕的问题与严重程度。
  - 明显问题（红）：语气词、上下文不符、空文本、起止时间无效、对齐/词时间错误、时长异常、确认的幻觉、建议合并。
  - 疑似问题（黄）：错字、谐音、漏字、多字、未匹配、歧义未确认、参考过期、超过每行字数。
  - 无上述问题时按“通过（绿）”显示；人工修改完成的条目优先显示绿色“修改完成”。
- `cueReportVerdict` 与 `verificationStatistics` 按上述规则统计通过/疑似/明显问题；`cueReportKey` 用“文字 + 毫秒起止”作为条目身份，`countChangedCues` 逐条核对原条目是否仍存在，拆分和改字都计入改动。
- 新增校验报告对话框（`#verificationReportDialog`）：上行为处理前，下行为处理后，显示总条数、改动条数以及通过/疑似/明显问题数量。
- “校准字幕”完成后对本次处理的条目、对齐字幕完成后对全部字幕重新调用 `rematchDerivedCues(..., {preserveModification:false})`，用最新校验结果替换“修改完成”等旧标签，再弹窗报告；报告统计与屏幕标签使用同一份结果。
- 表格字幕文字同步着色：通过绿色、疑似黄色、明显问题红色；红色样式优先于绿色。

### 2. 停顿阈值统一与参考句界

- 提取和对齐共用同一个“停顿断句”阈值（`gap_seconds`）：词间或音频静音达到阈值才拆，短于阈值不拆，0 关闭。
- 新增 `_reference_break_at(cue, cut)`：有可靠参考且未过期时，把字幕切点映射到参考字符位置，只有参考在对应位置有标点或换行才允许拆；参考写成一整句时，即使声音有明显停顿也不拆。
- 无可信参考、参考过期、未匹配或未确认歧义时返回 `None`，交给声音证据判断。
- `split_on_gaps` 在写入切点前调用该判断；参考断句才拆、参考句内不拆。

### 3. 对齐按字数分段

- 新增 `segment_alignment_cues(cues, max_width)`：对齐完成后按“每行字数”拆条，子条继承时间并衔接后面；对齐失败、词时间错误或结果过期的条目不拆，避免复制错误时间。
- `POST /api/alignment/jobs` 新增 `width_split`；普通对齐为 `true`，校准内部的对齐传 `false` 且 `gap_seconds=0`，保持校准前后条数一致。
- 对齐任务的停顿拆条和宽度拆条分别写入 `info.gap_splits`、`info.width_splits`，前端完成提示分行显示。

### 4. 版本与启动器

- 应用版本升到 `2.3.1`，同步打包清单、发布工具和回归记录。
- `backend/launch.py` 新增 `current_version()`：复用已运行实例前，比较 `/api/health` 返回的版本与磁盘 `backend/app.py` 的 `VERSION`；版本不一致时不再复用，避免升级后仍由旧后台处理请求。

### 5. 测试同步

- `tests/test_pauses.py`：对齐任务同时验证停顿拆条和宽度拆条；新增“参考一整句不拆、参考断句才拆”用例。
- `tests/frontend_regressions.mjs`：新增 `cueVerificationIssues`、`cueReportVerdict`、`verificationStatistics`、`countChangedCues`、`showVerificationReport`；新增处理前后统计与改动计数、超宽为疑似、空文本为明显问题、校准后重新校验替换“修改完成”并刷新报告用例。
- `tests/browser_smoke.py`：重新对齐和校准后断言报告对话框打开；校准后断言标签已变为“校验通过”，再关闭对话框继续后续检查。
