# 首次启动离线依赖与进度显示（2026-11-07）

对应应用 2.2.2。本轮把接收方首次启动的联网安装改为优先使用包内 wheel，并让安装/下载过程显示一行总进度条。

## 问题

- 发布包此前只带 Python 和依赖清单，接收方第一次启动需联网下载约 110 MB。
- 任一镜像超时后要等 60 秒 × 3 次重试才换下一个，最坏可达十几到二十分钟；pip 输出又只写 `data/logs/pip.log`，控制台看起来像卡住。
- 离线安装虽然快，但 pip 只打印零散行，看不出整体进度。

## 实现

1. 新增 `tools/prepare_wheels.py`：按 `requirements-lock.txt` 执行 `pip wheel --prefer-binary`，把直接和传递依赖全部放进 `wheels/`。jieba 没有现成 wheel，由 pip 现场构建。
2. 生成后用 `pip install --dry-run --ignore-installed --no-index --only-binary=:all: --find-links wheels -r requirements.txt` 验证这套 wheel 能独立装完运行依赖；用 `requirements.txt` 与锁文件的联合哈希判断 wheel 是否过期。
3. `tools/package_release.py` 把 `wheels` 收入发布包，清单增加 `offline_install`、wheel 数量和大小；缺 wheel 时默认拒绝打包，`--allow-online` 可显式生成联网包。
4. `打包到桌面.bat` 固定先运行 `prepare_wheels.py`（已就绪会立即跳过），再打包；`.venv` 缺失时用随包 Python 建一个只带 pip 的临时环境，保证删掉依赖后仍能打包。
5. 新增 `tools/pip_progress.py`：读取 pip 的 `Collecting / Downloading / Using cached / Processing` 行，按包名去重后显示一行总进度 `[####----] 12/27 当前包名`；完整输出写 `data/logs/pip.log`，失败时在控制台补印最后 20 行。
6. 新增 `tools/bootstrap_deps.py`：首次启动先试包内 wheels，失败再按五个镜像联网；脚本返回非零时 `run.bat` 回退到原批处理联网路径，避免进度条故障挡住启动。
7. `run.bat` 改为调用 `bootstrap_deps.py`，保留原批处理联网分支作为兜底。离线分支和打包下载共用同一进度条。
8. `prepare_wheels.py` 执行前检查 pip 是否可用，避免误用不带 pip 的随包 runtime。
9. 应用版本升到 2.2.2。

## 预期效果

- 首次安装约 1 分钟（视磁盘而定），不需要网络。
- 控制台显示总进度条，能看出已处理包数、总数和当前包名；不再长时间只有一行等待提示。
- 发布包增大约 110 MB。
- wheels 缺失、损坏或不匹配时仍回退联网，不会因此无法启动；进度条本身异常时也有批处理兜底。
