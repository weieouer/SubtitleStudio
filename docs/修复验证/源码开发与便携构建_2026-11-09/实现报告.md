# 源码开发与便携构建分离（2026-11-09）

按用户要求，当前目录作为正常 Python 源码项目维护，发布仍按原方法生成便携 ZIP。应用功能版本保持 2.3.4。

## 文件职责

| 文件/目录 | 职责 |
|---|---|
| `main.py` | 源码运行入口；从全局 Python 调用时切换到项目虚拟环境，直接运行后端，不安装依赖 |
| `dev.py`、`tools/development.py` | 显式创建/配置开发环境，按 requirements 和锁文件约束安装，执行依赖/导入检查 |
| `build.py` | 使用开发环境准备/检查离线 wheels，再按原规则构建便携 ZIP |
| `backend/`、`frontend/` | 继续维护现有后端与前端源码 |
| `tools/bootstrap.py` | 只处理发布后的便携首次启动，不再混合开发模式 |
| `tools/portable/run.bat` | ASCII/CRLF 发布模板，打包时映射为 ZIP 根目录的 `run.bat` |
| `pyproject.toml` | 统一源码工具设置；本项目以源码/便携 ZIP 发布，不新增 Python wheel 发行流程 |
| `.vscode/launch.json` | F5 直接使用开发虚拟环境调试 `main.py` |

本机的 runtime/wheels 保留为发布资源，开发环境与已有模型不搬动。上传源码仍按 `.gitignore` 排除环境、运行数据、发布资源与产物。任务栏重新启动现在根据入口选择 Python 源码或便携 BAT，不再引用不存在的根目录 BAT。

## 使用

```powershell
py -3.13 dev.py --setup-only
py main.py
py build.py --output ../releases/SubtitleStudio_portable.zip
```

更改依赖后维护 requirements/锁文件并重新执行 setup；日常运行不自动触发 pip。激活环境后也可直接 `python main.py`，`py dev.py` 保留为兼容入口。

便携 ZIP 继续包含源码、Python、离线 wheels 和当前界面参数；不含开发环境、模型、缓存和用户工程（除非显式启用 `--include-work`）。接收方解压双击 `run.bat`，首次自动创建环境，界面按需下载模型，行为保持原样。

## VS Code 日志问题

此前 `uv ENOENT` 来自全局 uv 已卸载、扩展仍默认调用 uv。本轮将用户设置的 `python-envs.alwaysUseUv` 设为 false，项目包管理器设为 pip，并把用户虚拟环境目录加入发现路径。用户设置原件已备份到 `%USERPROFILE%/.virtualenvs/_backups/vscode-python-settings-20261109.json`。

旧 pythonProjects 环境关联会优先使用项目内 `.venv`，已移除本轮无效关联；最新日志 21:24:54 明确记录工作区环境切换到 `%USERPROFILE%/.virtualenvs/SubtitleStudio/Scripts/python.exe`，来源为 defaultInterpreterPath。未向全局重新安装 uv 或其他项目依赖。
