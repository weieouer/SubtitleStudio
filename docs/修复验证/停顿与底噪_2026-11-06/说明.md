# 停顿、底噪与全局参数修复

## 问题与处理

1. 对齐接口把停顿阈值固定为0，任务后处理只对提取做停顿切分。现对齐也接收并应用同一阈值，提取/本段重识别/对齐共用切分函数。
2. 宽度分段清空词时间，修改停顿只保存设置。现可靠词时间随分段保留，词内切分标记估计；修改参数后通过 `pauses_only` 接口处理当前字幕，保留撤销，避免无必要重新识别。无可靠词时间不按比例猜文字，需要先音轨对齐。调大或关闭停顿不自动合并已经分开的条目。
3. 原底噪第20百分位估计会漏掉占比很小的短停顿。现在用持续60ms安静窗口辅助估计、加入自适应死区，频谱变化不能绕过低能量门槛。原始样本不被置零，识别模型仍接收原音频。
4. 明确的持续尾部静音可在词时间保护下收紧，保留原始时间并标待复核；只有能量证据、没有词时间时不大幅裁剪，避免误伤后半句轻声。静音边界保存在字幕元数据中，显示提前/延后和最短时长不会把空档填满。
5. 预览与导出共用换行格式化函数。对齐模式不适用的“仅人声”置灰，处理中会冲突的字幕限制控件全部禁用；其设置保留供下次适用时使用。
6. 右侧列表顶部固定一行“字幕 / 参考”，每张卡片去除重复标题，输入保留逐条无障碍名称，跟随滚动避开固定标题。

## 验证范围

- 后端142项通过，含11项专项：0.1秒浮点阈值、分段后再次切分、词间静音不被中点填满、拖长词尾、单词跨停顿不猜文字、短停顿占比低、轻声保护、持续底噪、参数传递及对齐任务后处理。合成音频测试确认原样本及原始记录保留。
- 前端36项通过：当前字幕按停顿切分与撤销、显示限制保护静音、预览/导出换行一致，以及已有状态回归，见 `前端回归.json`。
- 浏览器38项通过，结果见 `浏览器验证.json`；使用真实Chrome、真实本地HTTP接口及临时工程/配置，识别和对齐模型由测试替身提供，不加载用户正在运行的模型。覆盖固定列头、控件置灰、修改停顿立即切分、静音保护与换行切换。
- 上级 `后端回归.json` 及 `后端回归日志.txt` 记录本轮后端检查及源码哈希。本轮示例截图为 `界面_固定列头与停顿.png`。

自适应能量判断不能保证区分所有音乐、噪声与轻声；大幅收尾仍标待复核。没有把合成音频或替身模型结果当作真实成片的识别、对齐准确率证明。

## 生效

未停止或重启用户运行中的服务。先保存当前工程、等待任务结束，再重启后台并刷新页面。旧工程缺失词时间时先重新音轨对齐；调整停顿后可撤销，0只关闭后续切分，不会自动合并已有条目。
