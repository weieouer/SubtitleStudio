# GPU 环境按需安装与 CPU 回退

日期：2026-11-07
范围：`config/engines.json`、`backend/core/model_manager.py`、`backend/app.py`、前端设备区
结果：后端回归 **234 项通过**，浏览器联调 **53 项通过**

## 目标

- 当前不下载 CUDA：CPU 功能完整可用，发布包不因为 GPU 变大。
- 将来有人需要时，在界面点一次就能安装；装好即可选 GPU。
- 安装失败、驱动不可用或引擎加载失败时恢复 CPU 环境，软件仍能正常识别，可重试或改用 CPU。

## 配置

`config/engines.json`：

```json
"torch": {
  "mode": "manual",
  "cuda_index": "https://download.pytorch.org/whl/cu126",
  "packages": ["torch", "torchaudio"]
}
```

`manual` 与 `cpu` 一样在下载模型/配置环境时只装 CPU 版 torch，但不把策略锁死；界面仍可按需安装 GPU。`auto` 保留“检测到 NVIDIA 就随配置安装”，`cuda` 保留强制安装，供高级用户改配置使用。

## 后端

### 状态与就绪判断

- `desired_torch()`：`manual`/`cpu` 返回 `cpu`；`auto` 检测 NVIDIA 后决定；`cuda` 强制。
- `gpu_status()`：只读 `ready.json`，不触发安装；返回 `mode`、`nvidia`、`state`、`downloadable`、`size_hint`、`error` 和逐引擎的 `prepared`/`torch`/`cuda_available`/`error`。
- `state` 取值：`cuda`（全部引擎已装 CUDA）、`partial`（部分引擎）、`failed`（有 `gpu_error`）、`cpu`（环境已建但为 CPU）、`missing`（尚未配置 torch 引擎）。
- `runtime_ready()`：期望 CUDA 时，旧 CPU 环境视为未就绪；但带 `gpu_error` 的可用 CPU 环境算就绪，避免每次启动重下约 2.9 GB。
- `engine_gpu_ready()`：只认 `ready.json.torch == "cuda"`；ASR/对齐任务选 `cuda` 时由 `/api/jobs`、`/api/alignment/jobs` 提前拦截，返回中文提示，不会把 CPU 环境当 GPU 跑。

### 一键安装

- `POST /api/runtime/gpu` 调用 `ModelDownloads.start_gpu()`；已有下载任务时返回冲突提示，不并发写环境。
- 只给已经准备好的 qwen/firered 环境补装；一个都没有时提示先下载 Qwen 或 FireRed 模型。
- 每个引擎用 cu126 索引安装 `torch`/`torchaudio`，命令始终带 `--upgrade --force-reinstall`，避免已有 CPU torch 时 pip 报 `already satisfied` 却误标 CUDA。
- 安装后在对应 venv 里执行 `import torch` 并实测 `torch.cuda.is_available()`，再做引擎导入自检；通过才写 `ready.json` 的 `torch: "cuda"` 和 `cuda_available`。
- 进度复用模型下载状态接口和前端任务栏，`model` 字段为 `gpu`；支持取消，已完成的引擎保留。

### 失败回退

| 失败点 | 处理 |
|---|---|
| CUDA 下载/安装失败 | 自动重装 CPU 版 torch，`ready.json` 写 `gpu_error`，引擎仍可用 |
| CUDA torch 能装但 `cuda_available=False` | 记录 `torch: "cuda"`、`cuda_available: false` 和提示；运行时 `auto` 回退 CPU，显式 `cuda` 报错让用户改选 |
| CUDA 环境能导入但引擎自检失败 | 恢复 CPU 版 torch 并重新自检，写 `gpu_error` |
| CPU 版也装不上 | 明确报错并提示删除 `data/engines/<engine>` 后重新下载模型，不写就绪标记 |

## 前端

- 设备下拉下方新增 GPU 状态行（`#gpuState` / `#gpuStateText` / `#gpuDownload`）。
- 检测到 NVIDIA 时按状态显示：
  - `missing`：下载 GPU 环境 · 约 2.9 GB；
  - `partial`：补全 GPU 环境；
  - `failed`：重新安装 GPU 环境，并显示已回退 CPU；
  - `cuda`：GPU 环境已就绪；
  - 没有 NVIDIA 或没有 torch 引擎环境时给出对应说明，不显示无效按钮。
- 点击后调用 `/api/runtime/gpu`，按 `model === 'gpu'` 轮询进度，完成后刷新模型/GPU 状态；按钮忙碌状态与模型下载互斥。

## 验证

新增 5 项 GPU 单元测试（`tests/test_models_alignment.py`）：

- CUDA 安装使用 `--upgrade --force-reinstall`，实测输出 `cuda` 后写 `torch: "cuda"`、`cuda_available: true`；
- CUDA 安装失败后恢复 CPU，并保持 `runtime_ready()` 为真；
- GPU 补装失败恢复 CPU 并记录可重试错误；
- 没有已配置引擎环境时拒绝 GPU 下载；
- `gpu_status()` 正确区分未配置、CPU、CUDA、失败回退。

```text
.venv\Scripts\python.exe tests\run_backend_checks.py
{"tests_run": 234, "all_passed": true, "failures": 0, "errors": 0, "skipped": 0}

.venv\Scripts\python.exe tests\browser_smoke.py --url http://127.0.0.1:<fixture端口>
{"browser_checks": 53, "all_passed": true}
```

浏览器 fixture 固定返回 `nvidia: false`，GPU 行不进入主流程截图断言；GPU 状态渲染和按钮逻辑以单元测试和代码路径为准。

## 本轮没有做的事

- 没有实际下载 CUDA 包，也没有在真实 NVIDIA 显卡上跑识别；约 2.9 GB 的下载速度、驱动兼容性和 GPU 推理速度仍需目标机器验收。
- Whisper 的 GPU 仍取决于系统级 CUDA 12 cuBLAS/cuDNN 9 DLL，不在这套引擎 venv 的 torch 安装范围内。
- 已存在的 CPU 引擎环境不会自动升级；必须由用户点击一次 GPU 按钮。
