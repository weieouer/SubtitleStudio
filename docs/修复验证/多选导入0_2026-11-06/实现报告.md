# 多选剧本显示导入0：定位与修复

2026-11-06。

## 根因及复现

用户后台仍为10:01启动的旧进程，而页面JavaScript已由磁盘更新。新页面向/api/script/parse提交documents数组，旧后台忽略该字段，按缺少text处理，返回HTTP200、lines=[]、stats.total=0、document.version=1。页面原先未校验合并解析结果，直接覆盖了现有剧本并提示成功0段。

对当前运行后台只做内存解析请求验证，未读写用户工程：documents两份测试文本→0段/0字符/v1；旧text形式同样文本→2段/22字符/v1。结合进程启动时间，确认是新页面与旧后台混用。磁盘当前后端已支持documents和v2独立sources。

## 修复

frontend/js/app.js的applyScriptResult在修改任何状态前，检查非空lines、完整原文一致性以及来源数量。旧后台空成功或不一致响应会报明确错误，提示保存工程、结束任务后重启后台；不覆盖已有剧本、参考建议、来源、撤销/重做记录，也不触发保存。不会再把这类响应提示为成功导入0段。

没有新增静默兼容的拼接回退，以免在旧后台下把多来源乱序匹配错误当成成功。当前后台未被自动停止，用户正在编辑的页面与工程未操作。
