# 打包与首次启动

当前版本 3.2.2 · Windows x64 · Python 3.13。旧版本保留为历史基线和安装包。

**默认发布形态是完整 EXE 安装包（依赖内置）**：构建时把基础运行环境和 Qwen、FireRed 的推理依赖一并放入安装目录，用户安装后直接启动，只需在界面按需下载模型，安装版不再运行 pip。旧的在线/离线 wheels 形态保留为可选构建方式，便携 ZIP 工具也保留。

本文记录打包规则、文件白名单、首次安装/启动流程和依赖安装的终端显示。命令速查见 [README](../README.md)，架构背景见 [技术总览](技术总览.md)。

## 1. 发布形态

| 形态 | 产物 | 构建入口 | 特点 |
|---|---|---|---|
| 完整 EXE（默认） | `dist/full/SubtitleStudio-Setup-<版本>-x64-full.exe` | `py main.py build` | 运行库和全部推理依赖内置；安装后直接启动，仅模型按需下载；不运行 pip |
| 在线 EXE（可选） | `SubtitleStudio-Setup-<版本>-x64-online.exe` | `installer\build_installer.py`（不带 `--full`） | 不含依赖，首次启动联网安装；约 12 MB |
| 离线 EXE（可选） | `SubtitleStudio-Setup-<版本>-x64-offline.exe` | `installer\build_installer.py --offline` | 含 wheels，首次启动离线装依赖；约 116 MB |
| 便携 ZIP（旧） | `SubtitleStudio.zip` | `tools/package_release.py` 或 `tools/release.py` 的 `build_portable` | 保留工具与校验，默认 CLI 不再生成 |

安装版用户看到的是桌面/开始菜单快捷方式，**不需要手动运行 `run.bat`**。完整版的快捷方式直接指向安装目录的 `runtime\python\pythonw.exe -I backend\launch.py`；旧在线/离线版仍由 `run.bat`/EXE 完成环境准备。

### 自定义安装目录

首次安装和升级安装都显示“选择目标位置”，可直接输入路径或点击“浏览”，例如 `D:\字幕工作室\Subtitle Studio`。默认目录仍是 `%LOCALAPPDATA%\Programs\Subtitle Studio`；升级时预填上次目录，用户仍可更改。安装前会实际检查所选目录能否创建、写入和删除临时文件，无写权限时提示重新选择目录。静默安装可传入 `/DIR="D:\字幕工作室\Subtitle Studio"`。

工程、模型、引擎和日志保存在所选目录的 `data/` 下，快捷方式与卸载入口跟随实际安装路径。升级时更换目录不会自动迁移旧目录中的工程和模型；需要迁移时先关闭程序，再备份并复制原来的 `data/`。程序运行期间也需要目录写入权限，建议选择当前用户可写的磁盘目录。

## 2. 打包规则

### 2.1 默认构建链路

1. `py main.py build` 校验项目环境（Python 3.13 独立 venv，不继承系统包）。
2. `tools/release.py` 检查 `installer/build/prepared-runtime/manifest.json`；未就绪或依赖哈希已变化时，先运行 `tools/prepare_runtime.py`。
3. `prepare_runtime.py` 复制便携 Python 和 Qwen 推理环境，安装 CPU 版 torch/torchvision/torchaudio 及 FireRed 依赖，打包 FireRed SDK 源码，验证全部引擎入口与 `pip check` 后写入 manifest。固定版本的 wheel 从 `data/cache/runtime-build/wheels` 读取，避免构建时反复访问 PyPI；`pip check` 只放行 gradio 对 Pillow 12 的声明冲突（gradio 仅随 Qwen 包提供网页界面，不参与推理）。
4. 调用 `installer/build_installer.py --full`，默认输出目录 `dist/full`；目标 EXE 已存在时直接失败，不覆盖旧安装包（`--stage-only` 除外）。
5. 完整构建需要 Inno Setup 6 的 `ISCC.exe`；找不到时可用 `--iscc` 指定路径。
6. `--stage-only` 只生成暂存目录，不编译 EXE，适合交给已有打包工具或做启动验证。
7. 文件选择复用 `tools/package_release.py`，打包脚本不另写一份文件清单；`--full` 用 `prepared-runtime` 替换暂存的 `runtime/`。

完整版的 `runtime/python` 与 `runtime/ml` 均携带完整的 x64 Visual C++ CRT，避免在未安装微软运行库的电脑上对齐时报 `c10.dll / WinError 126`。构建时优先从 Visual Studio 的可再发行目录读取，也可设置 `SUBTITLESTUDIO_VC_REDIST_DIR` 指向 `x64/Microsoft.VC*.CRT`；没有指定目录时可使用构建机已安装在 System32 的运行库。所有必需 DLL 必须来自同一目录且为 x64，缺失时停止构建；旧的缺 DLL 运行库缓存不能继续发布。对齐进程在导入 PyTorch 前注册内置运行库目录。

旧安装包遇到截图中的 `Microsoft Visual C++ Redistributable is not installed` 错误，可先安装或修复[微软官方 x64 运行库](https://aka.ms/vs/17/release/vc_redist.x64.exe)，重启程序后重新对齐，无需重新校准或下载模型。其他模型/CUDA 错误仍保留原始诊断。

### 2.2 暂存目录

- 完整版：`installer/build/stage-full/`
- 在线版：`installer/build/stage-online/`
- 离线版：`installer/build/stage-offline/`
- 每次构建先清空暂存目录；安全校验要求它必须位于 `installer/build` 内，且不能等于该目录本身，防止误删源码。
- 文件复制用 `copy2` 保留时间戳；构建只读源码，不移动、不删除模型、引擎和 `.venv`。

### 2.3 完整版、在线版与离线版

- **完整版**用 `prepared-runtime` 替换暂存的 `runtime/`，包含便携 Python 和 Qwen/FireRed 共用推理环境；不打包 wheels。安装后启动不再运行 pip，模型由界面按需下载。体积明显大于旧安装包。
- **在线版**去掉 `wheels/`（约 106 MB），安装包约 12 MB；首次启动按镜像联网下载依赖。
- **离线版**保留 `wheels/`，安装包约 116 MB；首次启动优先用包内 wheels 离线安装。
- 在线/离线版构建前必须先准备 wheels；`build_installer.py` 不会自动下载。完整版由 `prepare_runtime.py` 自动准备依赖，构建机仍需访问 GitHub 与 PyTorch/PyPI 源。

### 2.4 便携 ZIP（旧规则，保留）

如需继续出便携包：

- 输出必须在项目目录之外，且目标文件不存在，不覆盖旧包。
- 构建前自动运行 `tools/prepare_wheels.py`，wheel 必须匹配包内 `runtime/python` 的版本。
- ZIP 顶层只有一个 `SubtitleStudio/`，附 `PACKAGE_MANIFEST.json` 记录每个文件的大小和 SHA256。
- 校验路径、必需文件、清单一致性、文件大小、CRC 和重复路径；先写 `.partial`，全部通过后才改名。
- 详细校验逻辑以 `tools/package_release.py` 为准。

### 2.5 不许做的事

- 不把 `.venv/` 复制进包；首次启动在安装目录重新创建。
- 不打包模型、引擎环境、缓存、日志和运行状态。
- 不把 `docs/`、`tests/`、`main.py` 放进安装版暂存目录。
- 不修改源码树以外的内容来“凑”安装包。
- `run.bat` 必须是 ASCII + CRLF；中文提示和逻辑放在 Python 里。

## 3. 打包哪些

### 3.1 安装版白名单

目录：

| 目录 | 内容 |
|---|---|
| `backend/` | 后端源码（含 `core/progress_console.py`） |
| `frontend/` | HTML / CSS / JS / 图标 |
| `runtime/` | 完整版：便携 Python、`ml/` 共享推理环境和 `manifest.json`；旧在线/离线版：便携 Python（`python.exe`、`pythonw.exe`、venv、ensurepip） |

根目录运行文件：

`run.bat`、`requirements.txt`、`requirements-lock.txt`、`config/engines.json`、`config/ui.json`、`tools/bootstrap.py`、`tools/pip_progress.py`。

完整版把 Qwen、FireRed 共用的 Python 运行时和推理依赖打进安装包，但不包含任何模型权重。模型权重在界面按需下载；旧在线/离线版仍可用，首次点击模型菜单会准备独立 CPU/GPU 环境。GPU 仍需兼容的 NVIDIA 驱动。应用 ID 和安装目录规则保持不变。

安装说明：

| 源文件 | 包内位置 |
|---|---|
| `installer/首次使用说明.txt` | `首次使用说明.txt` |

离线版额外包含 `wheels/`。

### 3.2 安装版不包含

`docs/`、`tests/`、`main.py`、`tools/` 下的其他工具（`prepare_wheels.py`、`package_release.py` 等）、`config/dialog_dirs.json`、`data/`、`.venv/`、`__pycache__/`、模型、引擎、缓存和日志。

### 3.3 旧便携 ZIP 白名单（保留）

- 目录：`backend/`、`frontend/`、`docs/`、`tests/`、`tools/`、`runtime/`、`wheels/`
- 文件：`main.py`、`pyproject.toml`、`.gitignore`、`README.md`、`requirements.txt`、`requirements-lock.txt`、`config/engines.json`、`config/ui.json`
- 模板映射：`tools/portable/run.bat` → `run.bat`，`tools/portable/首次使用说明.txt` → `首次使用说明.txt`
- `--include-work` 才额外包含 `data/projects/`、`data/results/`、`data/uploads/`、`data/outputs/`

### 3.4 必需文件

`tools/package_release.py` 的 `REQUIRED` 仍用于旧便携包和源项目完整性检查：

`run.bat`、`backend/app.py`、`backend/launch.py`、`frontend/index.html`、`backend/core/progress_console.py`、`tools/bootstrap.py`、`tools/pip_progress.py`、`requirements.txt`、`config/engines.json`、`runtime/python/python.exe`、`runtime/python/pythonw.exe`、`runtime/python/Lib/venv/__init__.py`、`runtime/python/Lib/ensurepip/__init__.py`。

安装版暂存时会再按 3.1 过滤；便携版统一由 `bootstrap.py` 完成首次启动检查与依赖恢复。

### 3.5 永远排除

| 类别 | 具体内容 |
|---|---|
| 环境 | 源码树的 `.venv/`、`.git/`、`data/engines/` 下的环境；唯一例外是 `tools/prepare_runtime.py` 显式生成的 `installer/build/prepared-runtime/` |
| Python 缓存 | `__pycache__/`、`*.pyc`、`*.pyo` |
| 临时文件 | `*.lock`、`*.tmp`、`*.part` |
| 符号链接 | 目录和文件都不跟随 |
| 运行数据 | `data/models/`、`data/engines/`、`data/cache/`、`data/run/`、`data/logs/` |
| 本机记忆 | `config/dialog_dirs.json` |

## 4. 构建命令

```powershell
# 准备/更新开发环境
py main.py setup

# 默认完整 EXE（依赖内置），输出到 dist/full
py main.py build

# 指定输出目录
py main.py build --output D:\releases

# 只准备安装文件，不编译
py main.py build --stage-only

# 指定 Inno Setup 的 ISCC.exe
py main.py build --iscc "C:\Users\Ouer\AppData\Local\Programs\Inno Setup 6\ISCC.exe"

# 旧在线/离线 EXE（可选，保留 wheels 或联网安装依赖）
runtime\python\python.exe installer\build_installer.py
runtime\python\python.exe installer\build_installer.py --offline

# 旧便携 ZIP（仍可用）
runtime\python\python.exe tools\package_release.py --output ..\releases\SubtitleStudio_portable.zip

# 校验旧便携 ZIP
runtime\python\python.exe tools\package_release.py --verify ..\releases\SubtitleStudio_portable.zip
```

`main.py build` 不提供 `--offline`、`--include-work`、`--allow-online`；这些只存在于安装器脚本或旧便携工具里。

## 5. 首次安装与启动（完整 EXE）

```text
双击 SubtitleStudio-Setup-<版本>-x64-full.exe
  └─ Inno Setup 安装到 %LOCALAPPDATA%\Programs\Subtitle Studio
       └─ 桌面 / 开始菜单快捷方式
            └─ runtime\python\pythonw.exe -I backend\launch.py
                 └─ http://127.0.0.1:8765/
```

### 5.1 安装

- 默认安装到当前用户目录，**不需要管理员权限**，不弹 UAC。
- 仅支持 Windows 10+ x64。
- 开始菜单创建主程序、首次使用说明和卸载项；安装目录内也放置“卸载 Subtitle Studio”快捷方式；桌面图标为可选任务。
- 卸载会删除程序文件、`data/`（工程、模型、引擎、日志、缓存）、`.venv/` 和运行时 `config/`；需要保留的工程应先备份到安装目录之外。
- 安装完成后可选择立即启动；静默安装时跳过。
- 完整版快捷方式直接指向 `runtime\python\pythonw.exe -I backend\launch.py`，不经过 `run.bat`。

### 5.2 完整版首次启动

- `runtime/manifest.json` 必须为 `ready`；缺失或损坏时提示重新安装，不在用户电脑联网补装。
- 直接使用内置 Python 和共享推理环境启动，不创建 `.venv`，不运行 pip。
- 自动创建 `data/` 及模型、引擎、日志、缓存、上传和输出目录。
- 模型权重不随包发布：Whisper、Qwen、FireRed 和对齐模型都在界面按需下载；GPU 加速可选，默认 CPU。
- 首次下载模型需要联网，之后识别与对齐可离线运行。

### 5.3 旧在线/离线版首次启动（可选）

旧形态仍由 `run.bat` 调用 `tools/bootstrap.py`，依次检查 Python、`.venv`、pip、运行依赖、程序文件和数据目录：

| 步骤 | 检查内容 | 缺失时的处理 |
|---|---|---|
| 1 | 包内 Python 可运行且 ≥ 3.12 | 提示重新安装 |
| 2 | `.venv` 存在、解释器指向安装目录、版本 ≥ 3.12 | 创建；旧环境改名为 `.venv.broken_<时间>`，改名失败则删除后重建 |
| 3 | venv 内可 `import pip` | 用 `ensurepip --upgrade` 补全 |
| 4 | `av`、`faster_whisper`、`numpy`、`jieba`、`rapidfuzz`、`pypinyin` 可导入 | 在线版按镜像联网安装；离线版优先用 wheels |
| 5 | `backend/app.py`、`backend/launch.py`、`frontend/index.html`、`requirements.txt` 存在 | 提示重新安装 |
| 6 | 创建 `data/`、`data/models`、`data/engines`、`data/logs`、`data/cache`、`data/run`、`data/uploads` | 自动创建 |

依赖安装顺序：有 `wheels/*.whl` 时用 `--no-index --only-binary=:all: --find-links wheels` 离线安装；否则按阿里云 → 清华 → 中科大 → 华为云 → PyPI 联网安装，超时 20 秒、重试 1 次。在线版首次启动必须联网；下载失败时重新启动即可重试。

### 5.4 启动结果

- 全部通过后提示“正在打开界面…”，由 `backend/launch.py` 启动服务并复用健康检查/后台机制。
- 界面地址默认 `http://127.0.0.1:8765/`，端口占用时顺延，只监听本机。
- 控制台关闭，服务在后台运行；再次点击快捷方式会复用现有服务。
- 日志位于安装目录的 `data/logs/`：`bootstrap.log`、`pip.log`、`launcher.log`、`app.log`。
- 界面内也可通过“帮助 → 终端”查看错误输出。

### 5.5 模型与引擎

- 模型不随安装包发布，首次启动不下载；磁盘需求取决于选择的模型，在下载界面查看。
- 在界面模型菜单按需下载：Whisper large-v3（识别）、Qwen3-ForcedAligner-0.6B（对齐）。
- Qwen / FireRed 引擎环境放在 `data/engines/<引擎>`，默认只准备 CPU；GPU 由界面明确触发安装。
- 首次下载和首次使用需要联网，之后识别可离线运行。

## 6. 依赖安装的终端显示

实现位于 `tools/pip_progress.py`，由 `bootstrap.py`、`development.py`、`prepare_wheels.py` 共用。

### 6.1 一行常驻进度

交互终端里始终只占一行，用 `\r` 回写，不滚动刷屏。两种形态：

```text
[########--------------]  12/27  下载 numpy
[##########------------]  62%  8.2/13.4 MB  下载 torch
```

- **包计数条**：总数来自 requirements / 锁文件的有效依赖行数（忽略注释和选项行）；进度按 pip 输出中首次出现的包名累计。
- **大小进度条**：从 pip 的 `Downloading ... 8.2/13.4 MB` 输出解析当前包大小；拿不到总量时只显示包计数。
- 非交互环境（输出被重定向、无 TTY）改为每行一条，避免 `\r` 污染日志。
- 换行宽度取终端宽度减 1，最小 30 列，超长内容截断。

### 6.2 其他可视化

| 场景 | 显示 |
|---|---|
| 六个启动步骤 | `[n/6] 名称 ... 通过 / 缺失，正在补全` |
| 创建 venv、`ensurepip` | 旋转指示器：`| 正在创建虚拟环境 12s` |
| 在线下载 | `包内没有 wheels，正在联网下载…`、`尝试 <镜像>` |
| 离线安装 | `使用包内 wheels 离线补全（N 个包）…` |
| 安装完成 | `[####...]  28/28  下载 完成` |
| 安装失败 | 打印最后 20 行输出，并指向 `data/logs/pip.log` |

### 6.3 降级与日志

- 完整 pip 输出始终写入安装目录的 `data/logs/pip.log`，进度条只负责显示。
- 若 `pip_progress` 导入失败或解析不到任何包名，自动退回直接输出 pip 原始内容，不阻塞启动。
- `pip_progress` 只影响显示，不改变安装命令和退出码。

## 7. 安装与卸载

### 7.1 安装

- 基于 Inno Setup 6，默认安装到 `{localappdata}\Programs\Subtitle Studio`。
- `PrivilegesRequired=lowest`：按当前用户安装，不需要管理员权限。
- 仅支持 Windows 10+ x64。
- 开始菜单创建：主程序、首次使用说明、卸载项；桌面图标为可选任务。
- 安装完成后可选择立即启动；静默安装时跳过。
- 首次启动流程与第 5 节一致：完整版直接调用内置 Python，旧在线/离线版调用 `run.bat`。

### 7.2 卸载

卸载会删除：

- `{app}\.venv`
- `{app}\data`（工程、模型、引擎、上传、输出、日志和缓存）
- `{app}\config`

需要保留的工程、模型或输出应在卸载前备份到安装目录之外。卸载行为与安装目录内的首次使用说明一致。

## 8. 升级与换机

### 8.1 升级

直接运行新版安装包覆盖升级时保留安装目录的 `data/`（工程、模型、引擎、缓存），替换程序文件。先卸载再安装会执行上一节的数据清理；需要保留的数据应先备份。

### 8.2 换机

- 安装版不包含用户数据目录里的模型、引擎权重、缓存和进程记录；完整版内置的是推理运行库，不是模型。
- 旧在线版首次启动需要联网下载依赖；离线版用包内 wheels；完整版不需要联网安装依赖。
- 工程、模型、引擎都在安装目录的 `data/` 下，迁移时备份整个 `data/` 即可。
- 工程以媒体路径为键，换机后旧绝对路径可能失效，需要重新关联。
- 目标机仍需 Windows x64 和 Chrome/Edge；GPU 驱动由目标机提供。
- 不要把软件安装到普通用户没有写入权限的目录。

## 9. 发布自检

```powershell
$projectPython = py main.py python

# 文档链接与过期命令
& $projectPython tools/check_docs.py

# 安装器选档、暂存清理边界和入口路由
& $projectPython tests/test_installer.py

# 准备并校验完整运行库，再只暂存完整版安装文件
& $projectPython -I tools/prepare_runtime.py
& $projectPython installer/build_installer.py --full --stage-only

# 旧在线安装文件首次启动（可选）
& $projectPython installer/build_installer.py --stage-only
& $projectPython tests/check_online_installer.py

# 开发入口 + 纯源码启动 + 便携首次启动
& $projectPython tests/check_development_release.py --output data/run/startup-check.json
```

`tests/check_online_installer.py` 只针对旧在线版：启动本地 HTTP 索引，真实下载并安装依赖，验证不依赖包内 wheels、服务能就绪、全局 Python 包列表未被改动。完整版则以 `prepared-runtime/manifest.json`、`pip check` 和引擎导入自检为准，并需在干净 Windows 机器上实测安装与启动。

## 10. 排错

| 现象 | 检查 |
|---|---|
| 安装包双击无反应 | 检查杀毒软件拦截；确认是 Windows x64 |
| 首次启动下载依赖失败 | 看 `data/logs/pip.log` 和 `bootstrap.log`；重新启动重试 |
| 快捷方式提示找不到 `run.bat` 或 `runtime\python\pythonw.exe` | 安装不完整，重新运行安装包 |
| 打包报“安装包已存在” | 换输出目录，构建不覆盖旧 EXE |
| 打包报 ISCC 找不到 | 安装 Inno Setup 6，或用 `--iscc` 指定路径 |
| 暂存目录报错 | 确认目录位于 `installer/build` 内；脚本拒绝删除其他位置 |
| 首次启动窗口一闪而过 | 在命令行运行安装目录的 `run.bat --console` 查看完整输出 |

## 11. 维护注意

- 版本号来自 `backend/app.py` 的 `VERSION`，安装包文件名和版本信息都用它。
- `run.bat` 仍是旧在线/离线版的快捷方式目标和 `REQUIRED` 项；完整版用 `runtime\python\pythonw.exe`。如果要彻底去掉 `run.bat`，需要同时修改 `installer/SubtitleStudio.iss`、`tools/package_release.py` 的 `REQUIRED`、`tools/portable/run.bat` 和 `tests/test_installer.py` 的断言。
- 便携清单的 `application_version` 从 `backend/app.py` 的 `VERSION` 读取，与安装包文件名保持一致。
- 重复的依赖安装脚本已移除，便携启动和修复统一使用 `bootstrap.py`；必需文件清单已同步。
- 安装版暂存目录只保留运行所需文件，不要把 `docs/`、`tests/`、`main.py` 加回去。
- `dist/` 下的旧 EXE 和 `installer/build/stage-*` 是构建产物，不参与发布包内容。
