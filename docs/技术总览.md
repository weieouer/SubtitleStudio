# 技术总览

当前版本 3.1.0，Windows x64 / Python 3.13；3.0.0 与 2.3.5 基线保留。完整安装包内置各引擎运行库，模型仍按需下载。本文只记录维护必须知道的设计；产品行为见 [需求与规范](需求与规范.md)，操作命令见 [README](../README.md)。

## 入口与目录

源码只有 `main.py` 一个入口，默认运行；`setup` 管环境，`build` 管发布，`python` 输出解释器。实现分别位于 `tools/development.py`、`tools/release.py`，不在根目录增加第二个启动脚本。

| 路径 | 职责 |
|---|---|
| `backend/app.py` | 本机 HTTP 服务、接口、配置、工程保存与导出 |
| `backend/core/jobs.py` | 串行识别/对齐任务、取消与结果 |
| `backend/core/removal_jobs.py`、`removal_models.py`、`removal_scan.py` | 消除任务、隔离模型环境、字幕出现时间检测 |
| `backend/removal_runner.py`、`frontend/js/removal.js` | 有限帧视频修复与独立的消除界面状态 |
| `backend/core/asr.py`、`external_asr.py`、`alignment.py` | Whisper、独立 ASR 引擎、强制对齐 |
| `backend/core/reference_match.py`、`calibration.py` | 多来源剧本匹配、内容校准与整理 |
| `backend/core/segment.py`、`audio_boundaries.py`、`duration.py` | 分段、语音边界与时长复核 |
| `backend/core/media.py`、`srt_io.py` | PyAV 解码/波形/MKV、SRT 输入输出 |
| `backend/core/model_manager.py`、`model_sources.py` | 模型下载、来源、引擎/GPU 环境 |
| `backend/core/storage.py`、`validation.py`、`paths.py` | 原子持久化、输入校验、统一路径 |
| `frontend/` | 原生 HTML/CSS/JS，app.js 管状态、编辑和渲染 |
| `tools/portable/`、`tools/bootstrap.py` | 便携发布模板与首次启动 |
| `tests/` | 后端、前端函数及隔离浏览器验证 |

无需 Node/Electron 或单独的 ffmpeg.exe；媒体处理使用 PyAV 自带库。源码运行前台便于调试，后台启动复用 `backend/launch.py` 的健康检查与日志机制。

## 环境与依赖

- 本机 Python 只创建环境，不安装项目依赖。默认使用项目内 `.venv/`，VS Code 解释器、F5 与终端激活使用同一路径；自定义环境用 `--venv` 或环境变量显式指定。
- 文件树显示全部文件，包括环境、缓存和发布资源；Git 忽略与搜索/监听排除不能作为隐藏文件的理由。
- 环境必须是独立 venv、Python 3.13，且不继承系统包。错误环境保留原目录，不自动删除；从其他 venv 调用也会切回指定项目环境。
- `requirements.txt` 管直接依赖，`requirements-lock.txt` 管传递依赖快照；更改依赖后共同维护，不用全局包列表覆盖锁文件。
- 安装命令固定到项目解释器，使用 pip 隔离配置及明确的子进程环境，避免用户 pip 设置重定向安装位置；不修改父进程环境。
- Qwen/FireRed 位于 `data/engines/<引擎>` 的独立环境；Torch/Transformers 不合并进主环境。依赖、源和自检声明见 `config/engines.json`。
- 默认只准备 CPU 环境。界面明确触发 GPU 安装，安装后实测 CUDA；失败恢复 CPU 并记录错误，避免每次启动重复下载。

## 数据与持久化

| 路径 | 生命周期 |
|---|---|
| `config/engines.json` | 随源码维护的引擎声明 |
| `config/ui.json`、`config/dialog_dirs.json` | 本机界面参数与目录记忆，不上传源码 |
| `data/projects` | 自动保存工程、原始记录和编辑状态 |
| `data/results` | 任务结果、初始字幕、波形等工作数据 |
| `data/uploads`、`data/outputs` | 拖入素材副本与输出 |
| `data/models`、`data/engines` | 权重与独立运行环境 |
| `data/cache`、`data/logs`、`data/run` | 缓存、日志、进程状态 |

路径依据 `backend/core/paths.py`，不依赖当前工作目录。工程以媒体/SRT 路径为键，并通过内容指纹查找相同素材；跨设备和移动素材不能假定原绝对路径仍有效。

工程写入采用跨进程锁、revision 检查、临时文件、fsync 和原子替换。409 后前端停止重复自动保存，先备份本页再载入最新工程。任务断线可停止等待并恢复编辑，原任务标识保留，重连查询以避免重复提交。

## 服务与处理边界

服务只监听 `127.0.0.1`。请求校验来源、会话 token、路径、类型、长度及数值；不要绕过 `validation.py`。完整 API 以 `backend/app.py` 路由为准，主要分为媒体/波形、模型/环境、任务、参考匹配、工程和导出。

识别/对齐由单 worker 串行执行。参考匹配使用独立的可取消任务，提供进度和 150 秒上限；输入规模有上限，不能宣称任意长剧本都能及时完成。

文本匹配使用 RapidFuzz、拼音与顺序约束，不调用大语言模型，也不能证明音频实际说了什么。RMS/VAD/字数时长仅辅助对齐；证据不足保留可复核的结果，不硬裁文字或强行拉散严重重叠。

必须保留 `asr_original`、原始文字/时间与来源。缓存、词时间、参考建议等派生结果在内容变化后要失效，不能当作新的原始记录。

## 发布契约

`main.py build` 默认调用 `tools/release.build_installer` 和 `installer/build_installer.py`，构建在线 EXE 安装包；文件选择复用 `tools/package_release.py`，不另写清单。

- 安装器暂存只保留 `backend/`、`frontend/`、`runtime/` 和运行必需文件；不打包 `docs/`、`tests/`、`main.py`、模型、引擎、缓存和日志。
- 在线版去掉 `wheels/`，首次启动按镜像联网安装；离线版保留 wheels，优先离线安装。离线版构建前需先准备 wheels。
- 暂存目录固定为 `installer/build/stage-online` 或 `stage-offline`，脚本拒绝操作该目录之外的位置。
- `run.bat` 是快捷方式指向的内部启动脚本，用户从桌面/开始菜单启动；BAT 必须是 ASCII/CRLF，逻辑放在 Python。
- 首次启动由包内 Python 创建安装目录的 `.venv`，逐项检查后启动服务；模型在界面按需下载。
- 安装包按当前用户安装到 `%LOCALAPPDATA%\Programs\Subtitle Studio`，不需要管理员权限。
- 旧便携 ZIP 工具与校验逻辑仍保留，但不再是默认构建路径。

本机 runtime/wheels 是被 Git 忽略的发布资源，开发运行不依赖它们。启动行为、会话校验、后台就绪检查和 Windows 禁端口复用规则必须保留。
