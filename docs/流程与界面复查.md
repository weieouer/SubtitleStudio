# 流程与界面复查

2026-11-12 更新，基于当前源码工作区。旧的完整安装包未包含本轮修改。

## 适合当前用途的流程

1. 有 SRT 就直接导入；没有字幕时先提取，保留初始识别记录。
2. 进入字幕校对模式，导入剧本，点击“校验字幕”。这一步只定位、标注，不改文字和时间。
3. 点击“校准字幕”，用可靠的对应参考纠正黄色文字差异；不自动增删条目。
4. 筛选并试听红色项：多识别、无可靠参考、参数不符。由用户手动修改；不从剧本生成空白字幕。
5. 内容确定后再“对齐字幕”，调整时间和分段；之后抽查开头、结尾、短字和长句边界，导出 SRT。

这个顺序合理。关键是校准和对齐之间加上人工复核红色项；对齐不能判断音频究竟有没有说出剧本里的一句话。之后若又改了文字，受影响条目需要重新检查音轨对齐。

## 已实际修改

- 校验、校准、对齐并排显示；校验入口不再藏在匹配参数折叠区。自动定位保留原勾选范围，也不会自动勾选第一条，避免下次校准意外只处理一条。
- 校准完成提示同时显示本次处理范围和全工程剩余错误，不再把“所选条目待复核为零”说成整份工程都没问题。
- “字幕限制”和时间微调操作放回视频下方、波形上方；按窗口高度保留预览和轨道空间。预览文字稍微上移，仅用于校对，不改变字幕文件的显示位置或时间。
- 下拉框改为标签筛选：轻微问题、明显错误、校验通过、校准通过、修改通过、对齐通过、未校验。取消独立缺失参考行和缺句小窗口；筛选不改导出内容。对齐完成后通过项显示“对齐通过”，人工修改或校准来源同时保留。
- 对齐前先检查词时间是否明显异常；异常项用原时间附近的局部音频重试，仍不可靠则保留原时间标红，不拿异常词时间拆句。
- “全选”和已选数量移到字幕列表上方左侧，与逐条复选框对齐。全选仍作用于全部字幕，标签/搜索仅改变可见范围；提示已说明这一点。
- 添加本地草稿恢复。保存失败后可在当前浏览器与地址恢复完整字幕、初始记录、剧本及设置。页面之间独立保存；新草稿不会被旧保存响应删除；恢复时服务器版本有变化则进入冲突处理，不能静默覆盖另一页。
- 素材失联仍可打开已有工程、修改、保存和导出 SRT。重新关联时保留字幕、初始记录及参考状态；新素材已有工程时先询问并备份。
- 撤销与重做分别按约 16 MiB 的序列化大小预算和最多 60 步裁剪，至少保留最后一个大操作。播放查询改为区间索引，保持跳播、重叠条目和排除状态的原行为。
- 模型下载锁改为按文件独立协调，避免慢下载阻塞无关工程保存；等待同一文件时仍可取消和超时。
- 打包复用补查 Python 窗口解释器及 Qwen/FireRed 入口；构建源环境的依赖元数据参与指纹。旧运行库需按新配方重新准备，不能继续用旧 ready 标记直接发布。

- 语气词开关开启允许保留，关闭时提取清理；导入或已有字幕只标红提醒。字数和时长参数不符同样标红，文字轻微不对应标黄。添加先输入文字，不创建空白行；清空字幕可撤销。

## 当前建议

优先建立一组真实素材验收样本：普通对白、连续短句、音乐、多人抢话和剧本漏句分别保留若干例子，比较错字、漏句/多句和头尾时间偏移。现在的自动化不能证明真实识别准确率。

大工程的下一步应做局部行更新或虚拟列表。当前合成 5000 条字幕全量渲染约 0.6 秒；本轮完成播放查询与历史内存保护，没有把整表更新问题标成已解决，也不建议为此引入整套前端框架。

局部重新对齐值得单独补充：只改了一两句文字时，可以只处理附近音轨，避免重跑全部字幕。目前仍使用现有全量对齐入口，未把这一项写成已实现。
