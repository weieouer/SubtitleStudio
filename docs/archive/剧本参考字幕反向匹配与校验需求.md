# 基于剧本参考的 ASR 字幕反向匹配与准确性校验

版本：2026-11-04。目标：辅助纠错字幕，而不是把剧本直接变成字幕。

## 1. 输入与责任边界

以 ASR 字幕为主体，输入字幕序号、原文、开始/结束时间及原始识别记录。原始 TXT 剧本只作参考，允许任意排版，不要求人物名、冒号、引号或对白格式；兼容现有 MD、DOCX 导入。

识别、文本校验、人工确认、音轨强制对齐是四个独立步骤。文本匹配不调用 Whisper、Qwen 或任何大语言模型，不听音频，不宣称能判断视频实际说了什么。剧本与成片有差异时，交由人工结合试听判断。

## 2. 不可变数据与标准化

- 保存剧本完整原文、非空段落、原始字符起止位置和物理行号。空行和 CRLF 保留在全文中。
- 使用 NFKC 统一全半角、兼容字符，统一大小写，删除标准化副本中的标点、空白及无意义特殊字符。
- 标准化按 Unicode 字簇进行；每个输出字符保存对应原始字符半开区间。一对多字符转换和组合附加符号不会丢失来源。
- API 位置以 Python Unicode 字符索引为单位，零基、结束位置不包含；界面显示一基位置和段落编号。
- 每条字幕保留 `asr_original`、`original_text`、`original_start`、`original_end`。人工操作只改当前文本或当前时间，不改原始记录。
- 原始视频、音轨、剧本和导入 SRT 不被覆盖；拖入的文件保存为工作副本。

## 3. 全文反向搜索

实现文件：`backend/core/reference_match.py`。

1. 为完整剧本建立标准化文本、字符位置映射、字符二元组及拼音二元组索引。
2. 每条当前字幕独立搜索，并组合相邻 1–4 条字幕辅助搜索；组合受时间间隔限制。
3. 从精确命中、二元组锚点和全文模糊搜索获取候选，在局部滑动窗口中调整片段起点与长度。
4. RapidFuzz 提供字符相似度，pypinyin 提供不带声调的拼音序列相似度，综合分增加长度差惩罚，避免过短截取片段抢占正确整句。
5. 使用按字幕顺序推进、受剧本位置约束的动态规划与有限束搜索选择组合。候选不能逆序、不能重复占用同一段参考文字，未匹配条目不会阻断后续重新定位。
6. 一条字幕可跨连续段落；多条字幕可对应同一参考段落，使用字符对齐映射将参考内容分配给各条，避免每条都重复填入整段文字。
7. 重复台词的其他位置保留为候选，结合前后锚点判断；仍无法唯一确认时显示多候选，不自动采用。

当前束宽 32，是有计算边界的全局顺序搜索，不宣称等价于穷举全部组合的数学全局最优。长稿件应按集处理，单份剧本上限 50 万字符、每次最多 5000 条字幕、单条最多 1000 字。

## 4. 分数与阈值

字符分、拼音分、综合分均为 0–1，界面以百分比显示。默认综合分以字符为主、拼音权重 0.25，拼音权重不得超过 0.4；拼音相同不会自动更正汉字。

可配置最低分、高分参考线、拼音相似门槛、候选分差和组合条数。默认分别为 0.64、0.94、0.90、0.035、3。1–3 字短句最低门槛至少 0.88，4–8 字也适当收紧。

分数不是识别正确率。即使分数很高，只要有实质字符差异，仍显示对应疑点；高分不能掩盖一处漏字或重复字。

## 5. 七类校验状态

| 状态 | 含义与处理 |
| --- | --- |
| 高度匹配 | 标准化后相同；不代表已经听音确认 |
| 疑似错字 | 存在替换差异，人工核对 |
| 疑似谐音 | 拼音分高于字符分且达到门槛，仅作疑点 |
| 疑似漏字 | ASR 相对参考存在插入位置，不自动补字 |
| 疑似多字 | ASR 相对参考存在删除位置，含重复字疑点 |
| 未匹配 | 无可靠参考、位置冲突或疑似叙述片段 |
| 多候选匹配 | 多个位置在可接受分差内，需确认参考位置 |

difflib 提供差异区间和字符：原字幕侧标出疑似错字/多字，参考侧标出对应文字/疑似缺少文字。标点和空白差异不作为汉字错误。

场次、动作、镜头等明确说明使用规则标记为仅供参考，不能直接作为可采用的对白建议。任意无格式叙述与对白之间不存在纯文本算法能够保证的语义分界，因此所有普通片段也只被称为“参考”，不被宣称为真实对白。无法判断时保持 ASR 并由人试听复核。

匹配位置之间未覆盖的剧本内容单独列作核查提示，可能为叙述、剪辑差异或 ASR 遗漏，不生成额外字幕，也不编造时间。

## 6. 右侧逐条双栏对照

右栏按 ASR 字幕序号连续排列，每条占一张卡片，可一直向下滚动：

- 左列：ASR/导入原文、当前字幕、原始时间戳。
- 右列：对应剧本原文、段落范围、字符位置。
- 卡片下部：字符分、拼音分、综合分、差异字符说明、其他候选。
- 点击卡片定位表格和预览；可试听当前句。

操作包括采用参考、保留原文、人工修改、标记非剧本、跳过、重新匹配。多候选必须先确认位置，才允许采用；不可靠或明确叙述候选不可直接采用。采用是明确的人工操作，支持撤销/重做。取消自动批量采用高相似文字。

改动当前文本后标记结果过期，重新匹配前禁止直接采用旧建议。跳过和非剧本标记在普通重新匹配时保留，单条重新匹配可解除标记。项目保存完整剧本、原始 ASR、当前字幕、校验结果及人工决定。

## 7. 模式与文件流转

- 字幕提取：媒体识别后生成 SRT，文件栏提供导出。
- 字幕对齐：保留刚提取的文件与当前字幕，文件栏作为 SRT 输入；支持点击或拖入 SRT。切换模式不会改动导入文件。
- 两种模式都显示识别设置；提取模式负责识别，对齐模式主按钮同一位置变为“对齐并校验”，也允许直接导入已有字幕。
- “对齐并校验”先以当前字幕文字对齐音轨，再运行全文参考校验；不自动采用剧本文字。单条采用后可重新运行，或在右侧独立重新校验。
- 剧本不参与强制对齐的文本生成。人工确认当前字幕后，Qwen3-ForcedAligner 只更新当前时间轴，保留原始时间，可撤销。
- 音轨对齐按原粗略时间划分不超过约 4 分钟的窗口，保留边缘余量；大幅错位应先粗调，不把局部精确对齐宣传为整集任意错位搜索。
- 当字幕切在一个模型词元内部时，词内分配边界标为估计，不能伪称每个字都有独立实测时间。

| 多人声音区分 | pyannote 可选扩展，当前未启用 |

## 9. 验收重点

验证无固定格式剧本、Unicode 位置保真、跨段参考、多条组合、错字/谐音/漏字/多字、重复台词多候选、顺序不交叉、未匹配后重新定位、跳过与重新匹配、原文与时间不被校验修改、人工采用/保留/修改/撤销、文件拖入及保存恢复。

文本校验使用真实后端进行专项测试。模型下载的传输/续传/取消通过小文件和模拟响应验证；没有下载并评测所有多 GB 模型，不能据此声称五个实模型在本机均已完整推理通过。

依赖与模型说明见 [模型与辅助模型接入](模型与辅助模型接入.md)，全局样式见 [UI 全局视觉规范](UI全局视觉规范.md)。
