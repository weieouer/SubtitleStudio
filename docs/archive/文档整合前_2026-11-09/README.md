# 文档索引

当前维护五份文档，各有唯一职责：

| 文档 | 读者 | 内容 |
|---|---|---|
| [../README.md](根目录_README.md) | 使用者 | 功能、模型、GPU、启动、打包、常见问题 |
| [技术总览.md](技术总览.md) | 维护者 / AI | 架构、模块、API、启动与依赖、引擎环境、GPU、打包、迁移约束 |
| [需求与规范.md](需求与规范.md) | 产品 / 前端 | 产品需求、反向匹配规范、UI 视觉规范、验收重点 |
| [开发记录.md](开发记录.md) | 维护者 / AI | 按日期倒序的每轮目标、实现步骤、验证结果与报告链接 |
| [问题与待办.md](问题与待办.md) | 维护者 / AI | 当前基线、问题与待办优先级、性能优化状态、已知边界 |

辅助目录：

| 路径 | 用途 |
|---|---|
| [修复验证/](../../修复验证) | 每轮的实现报告、回归 JSON、日志和截图；索引见 [修复验证/README.md](../../修复验证/README.md) |
| [versions/](../../versions) | 代码审查报告的历史版本 |
| [archive/](..) | 已合并或被取代的旧文档、历史记录；只读，不再更新 |

维护约定：

- 功能、架构、接口变化写进 [技术总览.md](技术总览.md)；产品行为和界面规范写进 [需求与规范.md](需求与规范.md)。
- 问题、待办和性能状态只写进 [问题与待办.md](问题与待办.md)，不为同一主题另建文档。
- 每轮开发结束，在 [开发记录.md](开发记录.md) 顶部加一条：目标、编号实现步骤、验证结果、详细报告链接。
- 详细报告和证据放进 `修复验证/<主题>_<YYYY-MM-DD>/`，报告统一命名 `实现报告.md`，并在 [修复验证/README.md](../../修复验证/README.md) 表格加一行。
- 验证数字只写实际运行并留存证据的结果；只更新用例未复跑时必须注明。
- 截图只展示最终项目界面，不收录修改过程中的工具栏迭代、波形对比等过程图。
- 旧文档被取代时移入 `archive/`，不要在两处同时维护。
