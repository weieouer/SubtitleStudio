# 字幕工作室 v2.3.4

本地字幕提取、音轨强制对齐和剧本参考校验工具。左侧设置参数，中间预览视频及音轨，右侧编辑字幕。后端使用 Python，前端为原生 HTML/CSS/JavaScript，不需要 Node、Electron 或独立的 FFmpeg 命令行程序，媒体处理使用 PyAV 自带的 FFmpeg 库。

## 本机开发

开发使用本机 Python 3.13，由它创建项目专用虚拟环境。项目依赖只装入虚拟环境，不安装到全局 Python。

```powershell
py -3.13 dev.py --setup-only  # 首次创建环境、安装依赖
py main.py                  # 日常运行源码，前台输出日志，Ctrl+C 停止
```

默认环境位于 `%USERPROFILE%/.virtualenvs/SubtitleStudio`，VS Code 的默认解释器也指向这里；F5 调试配置显式使用该解释器。`py main.py` 会在使用全局 Python 调用时切换到项目虚拟环境，不会启动安装流程。已有工作区若记住了旧解释器，请执行“Python: Select Interpreter”选择此环境。`py dev.py --print-python` 输出解释器路径；`dev.py --venv <目录>` 或 `SUBTITLESTUDIO_DEV_VENV` 可指定其他独立目录。`main.py --background` 可切换为后台启动，`--port`、`--no-browser` 等服务参数可以直接传入。`py dev.py` 保留为兼容启动入口。

安装额外依赖和运行检查时，明确使用开发环境解释器：

```powershell
$devPython = py dev.py --print-python
& $devPython -m pip install <包名>
& $devPython -m unittest discover -s tests
```

依赖变更同步维护 `requirements.txt` 和 `requirements-lock.txt`，再运行 `py dev.py --setup-only` 安装/检查。不要把全局环境的全部包直接冻结进项目。Qwen/FireRed 继续使用 `data/engines` 下的独立虚拟环境。开发环境安装失败时查看控制台和 `data/logs/pip.log`。

源码上传按 `.gitignore` 排除虚拟环境、`runtime`、`wheels`、模型、个人工程/设置、缓存和构建产物；发布资源在本机保留。便携打包仍需准备 `runtime/python` 和 `wheels`，从纯源码检出时可从既有便携包恢复这两项目录。准备 wheel 使用开发环境解释器，打包本身只使用标准库：

```powershell
py build.py --output ../releases/SubtitleStudio_portable.zip
```

便携包仍携带源码、Python 和离线 wheels，不携带本机开发虚拟环境或模型。接收方首次启动自动配置环境，进入界面后按需下载模型。

源码根目录使用 `main.py`（运行）、`dev.py`（配置环境）、`build.py`（准备依赖并打包）、`backend/`、`frontend/`、`tests/` 和 `tools/` 维护。`pyproject.toml` 统一源码工具设置，依赖仍由 `requirements*.txt` 管理。开发不依赖 BAT 或包内 Python。发布用 BAT 保存在 `tools/portable/run.bat`，打包时才放入便携 ZIP 根目录；源码中的 `runtime/`、`wheels/` 仅作为本机发布资源保留。

## 便携版安装和启动

当前主环境是 **Windows x64、Python 3.13.15**。只有源码时，新电脑需先安装同一 Python 3.13 系列版本，以及 Chrome 或 Edge；便携发布包已自带 `runtime\python`，不需要装 Python。

1. 解压整个项目，保留目录结构。
2. 双击唯一入口 `run.bat`；会检查或建立项目内 .venv，缺少依赖时优先从包内 `wheels\` 离线安装（约 1 分钟），没有 wheel 或安装失败时才按 requirements.txt 从国内镜像联网安装。安装过程在控制台显示一行总进度条（已处理包数/总数和当前包名），完整 pip 输出写入 `data\logs\pip.log`。
3. 以后仍双击同一入口启动。PowerShell 中使用 .\run.bat。
4. 下载所需主模型和辅助模型，准备对应的运行环境后再执行识别或对齐。

便携发布包由 `tools/package_release.py` 生成：包含源码、文档、引擎配置、当前界面参数、精简 Python 运行时和离线依赖 `wheels\`，不含模型及引擎环境。工程与素材是否加入由打包参数决定，实际内容见包内清单。

默认地址为 http://127.0.0.1:8765/。端口被占用时自动顺延，实际地址见启动提示。可用 run.bat --port 9000 指定起始端口。服务仅监听本机。

双击 run.bat 后会先出现一个启动窗口，显示检查与启动过程；确认网页及健康接口可用后，窗口自动关闭，服务转入后台运行（后台服务本身没有控制台窗口）。启动失败时窗口会停住并显示原因；重复启动会复用已在运行的服务，不会叠加多个后台进程。

排查问题可运行 run.bat --console，以前台控制台方式启动，Ctrl+C 停止。运行日志位于 data/logs/app.log，启动过程的输出位于 data/logs/launcher.log；程序内“帮助 → 终端”可实时查看运行状态、任务进度和报错（错误行标红），也可向上翻看历史日志。帮助对话框顶部显示软件名、当前版本、作者邮箱 weieouer@gmail.com 和“未经授权不得商用”声明。

## 使用流程

### 字幕提取

导入视频或音频，选择模型、设备、仅人声、语气词、停顿断句和每行字数，点击素材区的“提取字幕”。这是唯一识别启动入口。完成后自动生成 SRT，保存在 data/results/<任务ID>/<素材名>.srt。

### 字幕对齐

导入媒体和 SRT 后即可点击“对齐字幕”。它不做剧本参考校验，只按音轨更新每条的起止时间，并按“停顿断句”阈值把明显停顿拆成独立字幕条（短于阈值的停顿不拆，0 秒为关闭）；只拆不合并，两句话连着说时保持两条相邻字幕衔接。有可靠剧本参考时，参考写成一整句的停顿处不拆，参考在该处有标点断句才拆。过长字幕再按“每行字数”分段衔接后面，不改字词内容。字幕条长度随声音边界变化，并按文字数量设上限：几个字的短字幕被音效、句后杂音或相邻声音拉长到数秒时，会用语音活动收紧到真正说话的一段；整条被句前特效音带走、时长却正常时，会按对齐前粗时间附近的语音段重新锚定；证据不足时回退对齐前时间并标红待复核，不硬裁文字音频。文字错漏、多余内容的按参考补全或删除、标点、数字交给“校准字幕”。没有剧本也可以对齐；刚提取的字幕切换模式后自动沿用，也可点击或拖入已有 SRT。推荐顺序是“开始校验 → 校准字幕 → 对齐字幕”：校验只对照参考标出内容差异；校准按参考修正内容，参考里两句话就分段、一句话就合并，超过每行字数也分段，只改内容、不碰音轨；最后整轨校时并按声音停顿分段。通过标签随最后一次检查变化：校验通过 → 校准通过 → 对齐通过；疑似和明显问题三个步骤通用。标签只做标注，不自动关闭导出。

剧本支持 TXT、MD、DOCX，不要求人物名、冒号或固定对白格式。工作字幕、预览和导出统一使用简体中文；离线 OpenCC-js 1.3.1 随程序提供，原始 ASR 记录保留。右侧左栏为当前字幕，右栏为对应剧本参考（以简体显示，存储原文不改）；无对应内容时显示“尚无参考”。剧本仅用于校验，采用参考文字必须由用户操作，原 ASR、原始时间及剧本原文保留。

RapidFuzz、pypinyin、difflib、连续片段搜索和顺序约束用于查找错字、谐音、漏字、多字或多候选。分数阈值可配置。不能因剧本与音频不同就直接认定 ASR 错误，也不凭拼音自动改字。

## 字幕编辑

筛选、搜索和导出下方固定两排工具。编辑排依次为：合并、分段、添加、删除、撤销、重置。处理排依次为：关闭导出、重新识别、校准字幕、对齐字幕；后两项只在对齐模式显示。按钮均分可用宽度并适当加大，完整说明在悬浮提示里。全选和选中条目提示显示在标题行。字幕卡片可持续向下滚动；开启“跟随播放”后，列表和音轨跟随时间线。

- 单击字幕定位视频；Ctrl 点击可多选，并跳到最后点击的字幕，也可通过卡片复选框多选。
- 分段：只拆选中的当前句，在中间附近选择完整词边界，长句按字数上限均衡拆分；子条独立保留时间，不拼入下一条原字幕。子条编号如2.1、2.2。“已分段”仅提示原句超过字数限制后实际拆分，普通停顿拆条不显示该标签。
- 合并：选中两条或多条连续相邻字幕，文字按原顺序直接拼接（前一条在前），时间取第一条开始到最后一条结束；保留全部原 ASR 来源，可一次撤销。非连续多选不能合并。
- 添加：在空余时间内新增空白字幕；没有空间时提示先调整相邻字幕。
- 全选：勾选全部字幕，包括“不导出”条目，不受筛选或搜索影响；勾选仅用于批量编辑，不改变导出标记。
- 删除：删除全部勾选条目；撤销：一次恢复这批编辑。
- 重置：恢复本次提取或导入的全部初始字幕，包括文字、时间和导出状态。旧工程需保留初始 SRT 才能回退。
- 状态：通过标签为绿色，随最后一次检查变化——“校验通过 / 校准通过 / 对齐通过”；一般疑点、无参考、超过每行字数等为黄色“疑似问题”，参考中不存在的内容、上下文多余台词、空字幕、无效时间、对齐错误、异常拖长等为红色“明显问题”。整条笑声、叹气或填充音标红“语气词”。校准会把可靠参考中同属一句的相邻字幕自动并回一条；仍无法自动合并的疑似拆出单字、双字短碎片，该条文字变红并显示红色“建议合并”。直接修改文字后显示绿色“修改完成”，旧疑点不叠加；对齐只改时间，不会让“修改完成”失效。标签只做标注，不自动关闭导出；手动“不导出/加入导出”和仍保留的语气词保持原样。没有“完成”按钮及“已完成”“待重新校验”标签。
- 文字和开始、结束时间可直接编辑。时间位于序号后，显示到小数点后两位，内部和 SRT 仍保留毫秒精度。
- 关闭导出：选中条变灰，不参与预览和最终导出，可用“开启导出”恢复；导出标记独立于校验等级。
- 重新识别：两个模式均可用，支持多选/全选，按每条当前时间逐条识别；对齐模式有剧本时校验参考，其余字幕不替换。可取消，整批可一次撤销。
- 对齐字幕：对齐模式全局处理当前全部字幕，重新对齐音轨时间；同一句内明显停顿按“停顿断句”阈值拆条（短停顿不拆、0关闭），参考里明确是两句话时按句界分开、不受停顿阈值影响；过长字幕按“每行字数”分段衔接后面；不合并、不改字词，不受勾选范围限制。拆分出的子条继承原参考区间，完成后自动校验并弹出前后统计报告。
- 校准字幕：对齐模式处理勾选条目，未勾选时处理全部，支持全选且无10条限制；使用首轮有效参考，缺失或过期时内部按批次局部校验，再按参考补全漏字、删除多余内容并修正可靠的错字、谐音。参考里两句话被识别成一条字幕时，按参考句界自动分段（参考用换行或句末标点分句都有效）；可靠参考中同属一句的相邻字幕，在合并后不超“每行字数”时自动并回一条；参考里明确是两句话的保持分开；超过每行字数也分段。校准只改内容、不碰音轨，拆分合并后的时间先沿用原条目时间，留给最后的“对齐字幕”按音源重算。按“标点符号”开关保留问叹号或全部去掉标点；“阿拉伯数字”开关同步校准后的编辑、预览与导出。关闭“语气词”时直接删除整条笑声、叹气、填充音，并去掉句首、句末及句末标点旁的“啊、呀、哎、唉、哈哈”等语气词；开启时保留整条语气词，但可靠参考中没有的语气词仍会去掉。无参考或有歧义时不改字并提示；修改保留原ASR，整批可撤销。完成后按最新结果重新校验并弹出报告：处理前后的总条数、改动条数、校准通过/疑似/明显问题数量。标签不自动关闭导出。不再提供独立的“校验”“采用”“完成”小按钮。
- 校准后的整理：剧本/原文的明确句界会拆成独立条目，不将后半句拼到下一条；再按字数上限和导出状态整理。停顿拆条归“对齐字幕”，校准用停顿判断同一句的相邻条目是否自动合并。可靠参考中同属一句、合并后不超字数、停顿未达阈值的相邻字幕直接并回一条；参考里明确是两句话的保持分开，不受停顿阈值影响。其余疑似拆出的单字、双字短碎片（完整词跨界、共同原句或同句相邻可靠参考证据）不会自动合并，只把该条标红并显示“建议合并”；用户勾选该条与相邻字幕后点“合并”，文字按前后顺序拼接，时间取第一条开始到最后一条结束。遵守手动拆分边界，不跨未选字幕；有词时间保留真实词间静音，没有词时间则标为估计。
- 疑似幻觉字幕：提取、对齐、打开工程和导入 SRT 后自动检测，不需要手动触发。确认是片尾模板、字幕组声明等固定套话，或“时长 ≥20 秒且 ≤0.25 字/秒”的极端稀疏条目，默认不导出并变灰；其他可疑条目只显示“疑似幻觉·待确认”徽标，仍正常导出，由用户试听决定。手动改过文字或选择“恢复导出/纳入导出”后，不再重复提示。

连续 Whisper 识别复用当前已加载模型。切换模型、设备或转入其他引擎、强制对齐时释放缓存；首次加载仍需时间。其他隔离 ASR 引擎目前仍按任务启动。

快捷键：空格播放/暂停，Ctrl+Z 撤销，Ctrl+Y 重做，Ctrl+S 保存。

## 预览、音轨和字幕限制

- 视频画面在中间上方，叠加当前字幕，用于检查说话与字幕是否同步。
- 竖屏视频按原比例缩放、四周留黑边；预览区只占中间栏剩余高度，窗口变矮时预览先收缩，不会把下方字幕限制和时间轴挤出可见区域。
- 下方时间轴上层是字幕条，下层仅为音轨波形，共用刻度和播放位置，不显示视频缩略图。波形根据当前视窗自动归一化，并提供显示幅度滑块；波形的“波浪 / 矩形”按钮可在正常平滑包络和矩形柱状图之间切换，只改画法，不改变音量。选中字幕的首尾有拖动把手和贯穿波形的参考线，不改变实际音量。
- 点击或拖动音轨定位视频；音轨上的滚轮直接缩放，Shift+滚轮或横向滚轮平移。
- 底部滚动条平移音轨视窗，滑块比例随缩放变化；滚动条本身不改变播放时间。
- 按住字幕条中间可整体移动，首尾边缘可拖动伸长或缩短，受相邻字幕和视频边界限制。
- 可拖动时间轴上方横条调整轨道高度，左右分隔条调整侧栏宽度。
- 每行字数按实际字符计数，范围 6–30。生成分段和开启换行后的预览、导出均受限制。
- 提前出现、延后消失默认均为 **0 秒**，各自最多 1 秒；预览避免覆盖下一条，不改原ASR时间；导出始终使用编辑区当前起止值。
- 最短显示（0–10 秒）自动拉长短字幕，最长显示（0–30 秒）截断停留过久的字幕；0 为关闭，遇到下一条开始或媒体结尾即停止，只影响预览和音轨显示；导出使用编辑区当前时间，不加显示时长调整。
- 标点符号：开启只显示问号、感叹号，不显示逗号、句号等普通标点；关闭也隐藏问叹号。编辑框、参考、预览、音轨及导出同步；数字里的3.5、12:30、百分号和英文词内连接符保留。开关不改写底层原文；校准可从同字且可靠的剧本参考恢复语气标点，不凭空猜语气。关闭时编辑仍保留未改动区域的隐藏原标点。字幕换行：开启按字数限制换行，关闭合为单行。
- 仅人声控制识别前 VAD；对齐后的首尾边界二次校验始终使用内置 Silero VAD，不受该开关影响。疑似噪音、低置信字幕照常保留，底部显示总条数、已对齐和疑似条数，由用户决定是否排除。
- 语气词：关闭（默认）时，提取阶段直接删除整条只有笑声、叹气、咂嘴或“嗯、啊、呀、哼、呵”等填充音的字幕，并去掉对白句首、句末及句末标点旁的“啊、呀、哎、唉、哈哈”等语气词；句中的“你呀，就是……”以及“呢、吗、吧”等语法助词保留。开启时保留整条语气词并正常导出，但校准会按可靠参考判断：参考中没有的整条语气词或句末语气词仍会去掉。手动“加入导出”的条目不自动删除；手动改字或手动切换导出后以人工决定为准。
- 顶部音效开关及音量控制操作音和完成提示音。提取成功、对齐字幕完成和校准字幕完成均有提示。

## 对齐与分段算法

| 算法/工具 | 当前作用 |
|---|---|
| Qwen3-ForcedAligner-0.6B | 当前字幕文字与音轨的核心强制对齐 |
| RMS + Spectral Flux | 在已有时间附近辅助微调发音边界 |
| Silero VAD | 对每条字幕整段做二次人声判定；句首/句尾明确是非语音时收紧边界 |
| 自适应阈值 + Hysteresis | 根据局部噪声底，以进入/退出双阈值检测静音，减小抖动 |
| 单调与重叠约束 | 保护时间顺序、相邻字幕及视频边界 |
| DP + jieba + Python 规则 | 结合字数、词边界、标点和词时间停顿选择分段位置 |
| 参考句界约束 | 对齐遇到明显停顿时检查剧本对应位置：同一句内按声音停顿决定是否拆；参考里明确是两句话时按句界拆开，不受停顿阈值影响；无可靠参考时按声音停顿决定 |

RMS 边界每端最多微调 0.18 秒。若句首或句尾是 Silero VAD 明确判定的非语音（音乐、噪声、音效），可在保留首尾词的前提下继续收紧，单端最远 3 秒，尾音最多越过最后一个词结束时间 0.15 秒。VAD 不可用、证据不确定或可能裁掉整词时保留原时间。持续音乐、音效与多人重叠仍不能代替语义识别和人工试听。普通词尽量保持完整；单个词本身超过上限时允许切分。没有可靠词时间时标为估计，不把按比例分配时间当作精确对齐。

## 导出

右侧第一行“导出”可选：

- **SRT**：字幕文件，UTF-8 无 BOM、CRLF 换行。
- **MKV**：原视频、全部原音轨及当前校对字幕轨；不烧录字幕，不重新编码音视频。

导出应用当前标点、换行和数字设置，时间按编辑区当前起止值写入SRT标准毫秒格式。导出范围是全部未标记“不导出”的条目，不受勾选、搜索或筛选影响，即使全选也不会导出被排除的条目。确认格式后选择导出文件夹，记住上次导出位置；使用素材同名，重名自动加 _2 等后缀。时间无效、重叠或超出素材时阻止导出并提示。

拖入的素材会复制到 data/uploads；手动导出的目录由选择框指定，不必进入工作副本目录查找。MKV 是带独立轨道的媒体容器，其他编辑软件能否拆出字幕轨取决于其支持。

## 模型和独立环境

| 类型 | 模型 | 用途 |
|---|---|---|
| 主模型 | FireRedASR2-AED | 中文优先，短剧和口语场景更准；词级时间戳 |
| 主模型 | Whisper large-v3 | 多语言优先；词级时间戳 |
| 主模型 | Qwen3-ASR-1.7B | 方言更强；时间戳为分块估算 |
| 辅助 | Qwen3-ForcedAligner-0.6B | 字幕强制对齐 |
| 辅助 | Silero VAD | 随 faster-whisper 内置，无需重复下载 |

主模型三选一，不要求全部下载。中文普通话优先 FireRedASR2-AED，外语或中英混排优先 Whisper large-v3，方言素材优先 Qwen3-ASR-1.7B。继续原工作可优先恢复 Whisper large-v3 与 Qwen3-ForcedAligner-0.6B。

模型在 data/models，优先探测 ModelScope 与 HF 国内镜像，短采样测速选择来源，支持进度和续传。目录名和清单名不一致时也能按名称包含关系识别（如 my-whisper-large-v3-ct2）；仍认不出时可调用 `POST /api/models/locate` 手动指定目录（界面按钮待接）。Whisper 使用主 .venv；FireRed、Qwen（ASR 与对齐）在 data/engines 建立独立环境，pip 下载缓存统一放在 data/cache/pip，整个 data 目录可直接备份或迁移。各引擎的依赖、安装源和导入自检写在 config/engines.json，pip 源按阿里云、清华、中科大、华为云、腾讯云、官方顺序回退，界面点击下载模型时会按该配置一键安装环境。全部引擎声明、模型仓库及原电脑依赖快照见 MIGRATION.json。GPU 驱动、CUDA 和 PyTorch 版本需结合新电脑确认，不照搬旧虚拟环境。

### GPU 加速

- 默认 `torch.mode = manual`：下载模型、配置环境时只装 CPU 版 torch，**不会自动下载 CUDA**；CPU 功能完整可用。
- 检测到 NVIDIA 显卡时，界面“设备”下方会显示“下载 GPU 环境 · 约 2.9 GB”。点击后给已配置好的 Qwen/FireRed 环境补装 cu126 版 PyTorch，安装进度与模型下载共用同一任务栏，完成后可直接选择“自动”或“GPU (CUDA)”。
- CUDA 安装始终使用 `--upgrade --force-reinstall`，避免已有 CPU torch 的 venv 报“already satisfied”后被误标为 GPU；安装后用 `torch.cuda.is_available()` 实测再写 `ready.json` 的 `torch` / `cuda_available` 字段。
- 安装失败或驱动不可用会自动恢复 CPU 版 torch，`ready.json` 记 `gpu_error`，界面显示“GPU 安装失败，已回退 CPU”，可重试或继续用 CPU；失败过的环境不会在每次启动时重复尝试 2.9 GB。
- 设备选“GPU (CUDA)”但没有 CUDA 环境时，后端会提示先点“下载 GPU 环境”或改用“自动/CPU”，不会把 CPU 环境误当 GPU 跑。
- 开启 CUDA 后，Qwen 和 FireRed 走独立 venv 的 CUDA PyTorch，驱动正常即可用。Whisper 走 faster-whisper/CTranslate2，不读取引擎 venv 的 torch；要用 Whisper GPU 还需系统提供 CUDA 12 的 cuBLAS 与 cuDNN 9 DLL，否则“自动”会回退 CPU。

## 项目目录和迁移包

- backend、frontend：后端与界面源码、图标和资源。
- config/ui.json：参数、主题和界面配置。
- data/projects：旧工程和编辑状态；data/results：识别结果、初始 SRT 和波形。
- data/uploads、data/outputs：素材工作副本和输出。
- data/models、data/engines、.venv：权重和运行环境，迁移包不包含。
- wheels：离线依赖 wheel，发布包携带；由 `tools/prepare_wheels.py` 生成，首次启动优先从它安装。
- docs、tests、tools：文档、回归验证和维护工具。
- requirements.txt：直接依赖；requirements-lock.txt：打包时记录的完整主环境版本。
- PACKAGE_MANIFEST.json：当前发布包内文件、大小、SHA256和恢复方式；MIGRATION.json属于历史迁移工具格式。
- config/engines.json：各引擎依赖、安装源与导入自检。
- main.py：源码运行；dev.py：开发环境配置；build.py：便携 ZIP 构建。
- tools/portable/run.bat：发布模板，便携包根目录会生成 run.bat，首次配置环境并后台启动。

使用 `py build.py --output <项目外ZIP路径>` 准备离线依赖并生成便携包。低层 `tools/package_release.py` 继续保留原选档、`--include-work`、`--allow-online` 和完整性校验规则。本机模型与依赖不删除或搬动；生成后的便携 ZIP 带源码、Python 与离线 wheels，接收方首次启动自动配置环境。开发虚拟环境和便携环境分别管理。

包内 `PACKAGE_MANIFEST.json` 记录实际文件、大小、SHA256、wheel 数量和恢复方式；生成后校验必需文件、排除目录、文件哈希及ZIP完整性。完整解压后双击 `run.bat` 自动创建项目内 `.venv`，优先用包内 wheels 离线装依赖，缺失时才联网；再在界面模型菜单下载需要的模型。此包面向Windows x64，仍需Chrome或Edge；GPU驱动由新电脑提供。`MIGRATION.json` 是历史迁移方案格式，本轮发布包使用 `PACKAGE_MANIFEST.json`。
