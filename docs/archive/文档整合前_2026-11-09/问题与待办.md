## 二、当前待办

### 高优先级

| 编号 | 位置 | 问题 | 状态 |
|---|---|---|---|
| P1-对齐时长 | `backend/core/duration.py`、`backend/core/audio_boundaries.py` `cap_durations()`、`backend/core/alignment.py` | 短字幕对齐后被音效、句后杂音或相邻声音拉长到数秒（几个字占很长），或被句前突然的特效音带到音效位置上；字幕时长应与发声字数成比例 | 已做（2026-11-09，后端 272 项回归通过）：按字数给出时长上限，用 VAD/RMS 语音段收紧；长度正常但整条贴在音效上的，按对齐前粗时间附近的语音段重新锚定；证据不足回退对齐前输入时间并标记，输入时间也超限则只标待复核不硬裁。真实音效素材仍需人工试听验收 |
| P2 | `backend/core/reference_match.py`、`backend/app.py` 匹配路由 | 全文匹配在请求线程同步跑完，大剧本没有取消令牌和进度；前端超时后后端仍继续 | 已做（2026-11-09）：`core/match_tasks.py` 提供进度、取消、150 秒上限和单任务互斥；新增状态/取消接口，前端超时主动取消。超过时限返回可重试错误，不保存大结果 |
| L4 | `frontend/js/app.js` `applyScriptResult` / `applyScript` | 换剧本已清匹配建议和撤销/重做历史；剩余缺口是匹配结果未绑定剧本指纹，极端路径下旧建议仍可能被当作当前建议 | 部分 |
| P2-2 | `frontend/js/app.js` 任务轮询 | 服务断线后普通网络错误会一直退避重试，取消按钮也失败，`state.jobId` 不清空导致编辑被永久锁定 | 已做（2026-11-09）：断线时提供“停止等待，恢复编辑”，释放编辑锁并保留任务标识；“继续查询原任务”重连后取回结果 |
| P2-3 | `frontend/js/app.js` 自动保存 | 收到 409 后 `expected_revision` 停在旧值，本页自动保存会持续失败；提示语没有对应的“重新加载”操作 | 已做（2026-11-09）：409 后停止自动保存并保留本页修改，新增“备份本页并载入最新工程”，先备份再加载服务端最新 revision |
| P2-1 / P3-10 | `frontend/js/app.js` 全局 `keydown` | 焦点在按钮上按空格仍被当成视频播放/暂停，按钮无法用空格激活；`editing` 只判断输入框 | 已做（2026-11-09）：空格在按钮、链接、`summary`、`role=button/checkbox/slider`、视频和对话框内不再拦截 |
| L10 | `backend/core/model_manager.py` | 模型下载锁是进程内 `RLock`；两个后端共用 `data/models` 时 `.part` 仍可能互相踩。启动器单实例和 Windows 禁端口复用已缓解 | 部分 |
