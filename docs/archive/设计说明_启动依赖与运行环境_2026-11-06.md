# 设计说明：启动、依赖与运行环境

适用版本：2.1.0。最后更新：2026-11-06。
读者：后续维护者或其他 AI。本文记录**为什么这样设计**和**改动时必须守住的约束**，实现细节以代码为准。

---

## 0. 一句话总览

单入口 `run.bat` 负责自检主环境并后台启动服务；模型权重放 `data/models`，引擎依赖装进 `data/engines/<引擎>` 的独立 venv，pip 缓存放 `data/cache/pip`。引擎依赖、安装源和 GPU 策略集中在 `config/engines.json`，界面点“下载 / 配置环境”时按配置一键安装并用导入自检确认就绪。

## 1. 目录分层

| 路径 | 内容 | 打包 | 可删除 | 说明 |
|---|---|---|---|---|
| `data/models/<模型>/` | 模型权重、`.part` 片段、`.studio-model.json` | 否 | 是（需重新下载） | 只放权重，不放 Python 包 |
| `data/engines/<引擎>/` | 每个引擎独立的 venv、`install.log`、`ready.json` | 否 | 是（重新配置环境） | 版本互相隔离，避免 Torch/Transformers 冲突 |
| `data/cache/pip/` | pip 下载缓存 | 否 | 是 | 主环境和引擎环境共用 |
| `data/projects/`、`data/results/`、`data/uploads/`、`data/outputs/` | 用户工程和素材 | 是 | 否 | 打包保留 |
| `config/engines.json` | 引擎依赖、安装源、GPU 策略 | 是 | 否 | 唯一事实来源 |

**为什么依赖不和模型放一起**：模型目录会被 `weights_present()` 扫描，备份/迁移时按“权重”处理；把 venv 混进去会让体积统计、目录识别和迁移排除都变复杂。依赖本来就该在 venv 里，模型是数据，两者生命周期不同。

## 2. 启动链路

```
run.bat
  → 检查/重建 .venv（Python >= 3.12）
  → 检查主依赖，缺失时询问后 pip install -r requirements.txt
  → 设置 PIP_CACHE_DIR=<项目>\data\cache\pip
  → .venv\Scripts\python.exe backend\launch.py [参数]
       → 已有实例：打印“已在运行”，可选打开浏览器，倒计时 3 秒
       → 没有实例：用 pythonw.exe 后台启动 backend\app.py
       → 轮询就绪文件 + /api/health（带会话 token）
       → 成功打印地址，倒计时 3 秒后由批处理退出、控制台关闭
       → 失败写 data/logs/startup-error.txt 并返回 1
```

### 必须守住的约束

1. **`run.bat` 只能有 ASCII 字符，且保持 CRLF**。Windows cmd 在 OEM 代码页下解析批处理，UTF-8 中文注释可能吞掉换行，导致命令片段被当成指令执行（曾出现 `'击' is not recognized`）。需要中文提示就写到 Python 里。
2. **不要恢复 VBS 启动器**。用户要求只有一个入口文件；隐藏控制台由 `launch.py` + `pythonw.exe` + `CREATE_NO_WINDOW` 完成。
3. **不要重新打开 `SO_REUSEADDR`**。Windows 上它允许多个进程绑定同一端口，重复双击会悄悄堆出多个后台服务。`StudioHTTPServer.allow_reuse_address = os.name != "nt"` 是单实例安全的前提。
4. **实例地址写 `data/run/instance.json`**。启动器优先读它，避免逐端口探测；被防火墙丢包的端口每次会等满超时，30 个端口能把启动拖慢近 10 秒。只有状态文件缺失时才扫描附近 6 个端口。
5. **启动成功要有 3 秒倒计时**，让用户看清地址和错误；不要改回“闪一下就没”。
6. `--console` 是排障入口：前台运行 `app.py`，日志直接进控制台。`--no-browser` 只影响是否打开浏览器。

### 运行状态与终端

- `app.py` 写 `data/logs/app.log`；`/api/health` 返回 `ok`、`version`、`models`、`auxiliary`、`data_dir`、`uptime`、`port`、`log_file`。
- `/api/logs` 提供日志尾部；右上角“帮助 → 终端”轮询这两类接口，状态栏保持单行，并按级别着色。
- 轮询日志和任务接口不写访问日志，避免刷屏（`Handler.log_message`）。
- 终端对话框的 DOM/CSS/JS 在 `frontend/`，后端只保证接口字段稳定。

## 3. 模型下载

- 模型清单在 `backend/core/model_manager.py` 的 `CATALOG` / `AUXILIARY`；`ALL_MODELS` 合并两者。未知名字一律拒绝，不允许下载任意 URL。
- 下载目标固定为 `data/models/<name>`，支持历史别名（`MODEL_FOLDER_ALIASES`），方便直接识别手动放进来的权重目录。
- 目录名和清单名不一致时，按以下顺序找（`model_directory()`）：
  1. 用户在界面上手动指定的目录（`data/models/.locations.json`）；
  2. 清单名与历史别名；
  3. 名称包含匹配：去掉分隔符后比较，`my-whisper-large-v3-ct2` 能认成 `large-v3`；多个模型名都能匹配时只判给匹配最长的一个；
  4. 都没有才回退到 `data/models/<name>`（下载目标）。
- 手动指定走 `POST /api/models/locate`：`{"model":"large-v3","path":"D:/模型/自定义目录"}`，`path` 为空表示恢复默认。前端先用 `/api/dialog` 的 `kind:"dir"` 选目录再调用它；目录里必须有 `model.bin` / `model.safetensors` 等权重文件，否则返回 400。
- 这层映射只影响读取位置，不改文件、不复制权重；移动或删除目录后自动失效并回退默认路径。
- 文件先写 `.part`，用 `Range` 续传；校验 `Content-Range` 起点和总长度；有 SHA-256 就校验；完成后原子替换。
- 多源：ModelScope → HF-Mirror → Hugging Face 官方，短采样测速排序（见 `core/model_sources.py`）。
- 完成后写 `.studio-model.json`（仓库、revision、来源、文件大小和哈希）；`weights_present()` 用它判断完整性。Qwen 允许没有 manifest 时按关键文件判断。
- 下载过程中有 `.studio-downloading` 标记；取消保留片段，下次继续。

## 4. 引擎隔离环境

每个引擎一个 venv：`data/engines/<engine>`，通过 `engine_runner.py` 子进程调用，主 `.venv` 不装 Torch/Transformers。

安装流程（`ModelDownloads._prepare`）：

1. `runtime_ready(engine)` 为真则直接返回。
2. 创建 venv（`with_pip=True`）。
3. 若该引擎声明了 `torch: true` 且当前策略是 CUDA：先装 `torch`/`torchaudio`（见第 6 节）。
4. 按 `indexes` 顺序安装引擎包，任一源成功即停止；失败换下一个源。所有 pip 子进程共享 `PIP_CACHE_DIR`。内置顺序：阿里云 → 清华 → 中科大 → 华为云 → 腾讯云 → PyPI 官方。
   - 注意：换源只解决“镜像不可用”。如果失败原因是依赖解析冲突，换源同样会失败，应该改 `packages` 里的版本约束。
   - Qwen 必须同时装 `gradio<6`：`qwen-asr==0.0.6` 只写了 `gradio` 不带上限，而 gradio 6.x 要求 `huggingface-hub>=1.0`，与 `transformers==4.57.6` 的 `<1.0` 冲突。不加上限时 pip 会逐个回退 gradio 6.30、6.29……每试一个都下载约 30 MB 的 wheel，看起来像“卡住”，最后还可能失败。加上 `gradio<6` 后一次解析成功。
   - `qwen-asr` 的元数据没有声明 `torch`，但代码顶部 `import torch`；实际由 `accelerate==1.12.0` 带入 PyTorch（Windows 上 PyPI 的 torch 即 CPU 版），所以 CPU 模式不需要额外预装。
   - **中文路径限制**：qwen 依赖的 `nagisa` 用 DyNet（C++）读取 `nagisa_v001.model`，Windows 上走窄字符接口，项目路径含中文时必定失败（报 `Could not read model from …`）。`patch_nagisa_model_path()` 在 pip 安装后、导入自检前改写引擎 venv 里的 `nagisa/tagger.py`：把模型复制到 `%PUBLIC%\SubtitleStudio\nagisa\nagisa_v001.model`（纯英文路径）并改用该路径。纯英文路径下不加任何改动；重装依赖后补丁会重新应用。若系统连 `%PUBLIC%` 都不是英文路径，自检失败信息会提示把项目移到纯英文目录。torch 等其它依赖不受此问题影响。
5. 用配置里的 `probe` 做导入自检，失败则不写就绪标记。
6. 写 `ready.json`：`engine`、`packages`、`indexes`、`torch`（实际装的是 `cuda` 还是 `cpu`）、`prepared`。

`runtime_ready()` 的语义：

- `whisper` / `builtin` 永远就绪（用主环境或内置资源）。
- 其他引擎必须同时存在 venv 的 Python 和 `ready.json`。
- 如果引擎声明 `torch: true` 且 `desired_torch() == "cuda"`，还要求 `ready.json.torch == "cuda"`。这样把 `torch.mode` 从 `cpu` 改成 `cuda` 后，旧的 CPU 环境会被视为未就绪，下次“配置环境”自动补装，不需要手动删目录。
- 反过来，期望 CPU 时接受已有的 CUDA 环境（CUDA 版 torch 本来就能跑 CPU），不会白白重装。

取消：`cancel_event` 触发时终止 pip 子进程，保留已下载的 pip 缓存。

## 5. `config/engines.json` 契约

```json
{
  "version": 1,
  "pip_cache": "data/cache/pip",
  "indexes": ["镜像1", "镜像2", "官方"],
  "torch": {
    "mode": "auto",
    "cuda_index": "https://download.pytorch.org/whl/cu126",
    "packages": ["torch", "torchaudio"]
  },
  "engines": {
    "qwen": {
      "packages": ["qwen-asr==0.0.6", "gradio<6"],
      "probe": "from qwen_asr import Qwen3ASRModel, Qwen3ForcedAligner",
      "torch": true
    }
  }
}
```

| 字段 | 作用 | 非法时的行为 |
|---|---|---|
| `pip_cache` | pip 缓存目录，相对路径按项目根解析 | 回退 `data/cache/pip` |
| `indexes` | 全局 PyPI 源，按顺序回退 | 回退内置六个源（见第 4 节） |
| `torch.mode` | `auto` / `cpu` / `cuda` | 回退 `auto` |
| `torch.cuda_index` | CUDA 版 torch 的索引 | 回退官方 cu126 |
| `torch.packages` | 预装的 CUDA 包 | 回退 `torch`、`torchaudio` |
| `engines.<name>.packages` | 该引擎的 pip 参数 | 回退内置声明 |
| `engines.<name>.probe` | 导入自检语句 | 回退内置语句 |
| `engines.<name>.indexes` | 覆盖全局源 | 回退全局 `indexes` |
| `engines.<name>.torch` | 该引擎是否使用 GPU 版 torch | 回退内置值 |

- 配置按“路径 + mtime”缓存，改文件后无需重启即可影响下一次安装；但 `RUNTIME_PACKAGES` / `RUNTIME_INDEXES` 是导入时的快照，只用于兼容和测试断言，**新代码不要在运行时依赖它们**。
- 只允许内置的三个引擎名；新增引擎不能只改 JSON，还要在 `CATALOG`、`engine_runner.py`、`asr.py`/`external_asr.py` 增加调用逻辑。
- 安装源必须是完整的 pip `--index-url`（simple 索引）。阿里云的 `pytorch-wheels` 是文件列表页，不是 simple 索引，不能直接填 `cuda_index`。

## 6. GPU 设计

GPU 有两层，必须同时满足：

1. **Python 包层**：引擎 venv 里装的是 CUDA 版 torch，`torch.cuda.is_available()` 为真。
2. **任务设备层**：界面“设备”选 `auto` 或 `cuda`，任务才会把设备传给引擎；`cpu` 即使装了 CUDA torch 也按 CPU 跑。

### 6.1 策略与检测

- `torch.mode = auto`：用 `nvidia-smi --query-gpu=name` 检测 NVIDIA 显卡，有就按 CUDA 装。检测结果进程内缓存一次。
- `torch.mode = cuda`：强制 CUDA；`cpu`：强制 CPU。
- **当前仓库随附配置为 `cpu`**：优先控制下载体积，Qwen 对齐在 CPU 上也能跑。有需要再改成 `auto`/`cuda`，下次“配置环境”会补装 CUDA torch。
- 安装顺序：先用 `torch.cuda_index` 单独装 `torch`/`torchaudio`，再从普通镜像装引擎包。这样 `qwen-asr` 解析到已安装的 torch，不会又装一份 CPU 版。
- 实测官方 cu126 源能解析出完整的依赖树（torch、torchaudio、sympy、networkx、jinja2 等），因此只用一个 `--index-url` 即可；不要换成文件列表页。
- CUDA 版 torch 首次约 2.9 GB，之后走 `data/cache/pip`。安装失败直接报错并提示把 `mode` 改成 `cpu`，**不做静默回退**：GPU 是用户显式想要的能力，失败要看得见。

### 6.2 引擎差异

| 引擎 | 是否装 CUDA torch | 原因 |
|---|---|---|
| qwen | 是 | ASR 和 ForcedAligner 都走 torch，GPU 收益最大 |
| firered | 是 | 模型推理走 torch |

### 6.3 Whisper 的特殊情况

Whisper 走 faster-whisper/CTranslate2，**不读取引擎 venv 里的 torch**。要让它用 GPU，系统必须能加载 CUDA 12 的 `cublas64_12.dll` 和 cuDNN 9 的 `cudnn64_9.dll`；`asr._cuda_runtime_ok()` 会检查 cuBLAS，缺失时 `auto` 自动回退 CPU。

因此当前状态是：Qwen/FireRed 可用 GPU，Whisper 默认 CPU。若要给 Whisper 开 GPU，需要把 `nvidia-cublas-cu12`、`nvidia-cudnn-cu12` 装进主 `.venv`，并在加载模型前把对应 `bin` 目录加入 DLL 搜索路径。这是独立的后续工作，不要和引擎 venv 的 torch 混淆。

### 6.4 显存

4060 8GB 跑 Qwen 0.6B 对齐或 1.7B ASR 单任务没问题；不要假设大模型和辅助模型能同时常驻显存。

## 7. 打包与迁移

2026-11-06实际发布工具为`tools/package_release.py --output <桌面ZIP路径>`；下方`package_migration.py`是历史设计，当前目录未提供。轻量包保留便携Python、程序、文档/验证、依赖声明、引擎配置和当前界面参数；排除模型、虚拟环境、缓存、日志、进程状态、旧目录记忆和Python缓存。可用`--include-work`带工程/结果/项目内素材/导出，但绝对工程路径需在新设备重新关联。`PACKAGE_MANIFEST.json`记录实际内容、大小和SHA256；打包后检查哈希、ZIP CRC、必需文件和排除目录。仅只读打包，不删除或搬动本机模型与依赖。

`tools/package_migration.py`：

- `EXCLUDED = {data/models, data/engines, data/cache}`，`.venv`、`__pycache__` 等在 `PRUNE` 中。
- 生成后会校验包内不得出现 `/.venv/`、`/data/models/`、`/data/engines/`、`/data/cache/`、`/__pycache__/`。
- `MIGRATION.json` 的引擎依赖声明改为读 `config/engines.json`，不再从 Python 源码里解析 `RUNTIME_PACKAGES`；`torch` 策略也会写入声明。
- 新电脑恢复顺序：解压 → 双击 `run.bat` 重建主环境 → 在界面下载模型/配置环境（按 `engines.json` 一键装引擎）→ 迁移工程路径。
